Create a field alias map that bridges the naming gap between the triangulation pipeline's canonical field names and the XBRL engine's internal field names, then snapshot both pipelines as pre-fix baselines for regression tracking.

Purpose: ~80% of the 2,786 triangulation "bugs" are false positives caused by naming mismatches (e.g., source says `stockholders_equity`, engine says `equity`). The alias map eliminates these without touching any engine code. The baselines enable regression diffing after every subsequent fix batch.

Output: field-alias-map.mjs with 16+ aliases, integrated into triangulate.mjs, with unit tests and pre-fix baseline snapshots of both pipelines.
</objective>

```javascript
function collectAllFields(engineData, sources) {
  const fields = new Set();
  function addFields(data) {
    if (!data) return;
    for (const stmtKey of ['income', 'balance', 'cashFlow']) {
      if (data[stmtKey]) {
        for (const yearData of Object.values(data[stmtKey])) {
          for (const field of Object.keys(yearData)) {
            fields.add(field);
          }
        }
      }
    }
  }
  addFields(engineData);
  for (const s of sources) { addFields(s.data); }
  return [...fields].sort();
}

function getFieldValue(data, field, year) {
  if (!data) return null;
  for (const stmtKey of ['income', 'balance', 'cashFlow']) {
    const val = data[stmtKey]?.[year]?.[field];
    if (val != null) return val;
  }
  return null;
}
```
