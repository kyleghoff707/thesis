## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge padding, close button padding |
| sm | 8px | Compact element spacing, timeline card gap, checklist item padding |
| md | 16px | Default element spacing, panel padding, card padding |
| lg | 24px | Section padding, hero spacing |
| xl | 32px | Empty state top padding |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Not used this phase |

Exceptions (sub-4px and non-scale values retained for codebase consistency):

| Value | Component | Justification |
|-------|-----------|---------------|
| 2px (vertical) | Category badge `padding: 2px 8px` | Matches established pattern in ConfidenceBadge, ResearchList stage pills, Validation badges, DebateRenderer round badges, Competitors score badges, and Watchlists badges -- all use `2px 8px`. |
| 3px (vertical), 10px (horizontal) | Status badge `padding: 3px 10px` | Matches VerdictBadge (line 57: `isLarge ? '6px 16px' : '3px 10px'`), ResearchList stage pills (lines 150, 169, 190), ReportsList (line 87), Insiders (line 369), StockAtGlance (line 212), and FullStory (line 42). Changing would create visual inconsistency with 15+ existing badge instances. |

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 13px | 400 | 1.7 |
| Label | 10px | 700 | 1.0 |
| Subhead | 12px | 700 | 1.5 |
| Heading | 16px | 700 | 1.2 |

Two weights only: 400 (regular) and 700 (bold).

Source: Extracted from existing components. All Phase 23 components use these four tiers exactly:
- **Body** (13px/400/1.7): Narrative text, evidence, deep dive content, promise quotes, glossary definitions. Matches SectionRenderer narrative and ChecklistRenderer evidence.
- **Label** (10px/700): Uppercase category labels ("DEFINITION", "INDUSTRY BENCHMARK", "KEPT", "Q3 2024"). Matches IndustryCard labels and VerdictBadge/ConfidenceBadge patterns. Always uppercase, letter-spacing 0.04em.
- **Subhead** (12px/700): Timeline card quarter tags, aggregate score text, section sub-labels. Matches ChecklistRenderer score text and DebateRenderer sub-labels.
- **Heading** (16px/700): Panel titles, section headers. Matches DeepDivePanel and SectionRenderer section headers.

## Component Inventory

### 1. Deep Dive — "Tell me more" Links (SectionRenderer enhancement)

**Trigger:** Inline text link within narrative content, rendered from `notableClaims[]` array per section.

| Property | Specification |
|----------|---------------|
| Element | `<span>` with click handler, styled as inline link |
| Text color | `C.accent` |
| Font | 13px, weight 700 |
| Cursor | `pointer` |
| Hover | Underline via `textDecoration: 'underline'` |
| Icon | None (text-only link, avoid visual clutter in narrative) |
| Position | Inline within paragraph text, after the notable claim sentence |
| Format | ` Tell me more` (space before, no period after) |

**Interaction:**
1. User reads narrative and sees "Tell me more" link after a notable claim
2. Click opens DeepDivePanel (existing component) with claim context
3. Panel shows loading spinner while Claude API call executes (~3-5s)
4. Response renders as paragraphs in the panel content area
5. "Go Deeper" button appears below the response for iterative deepening
6. Deep dive content saved to report JSON on completion

### 2. Deep Dive — "Go Deeper" Button (DeepDivePanel addition)

| Property | Specification |
|----------|---------------|
| Element | `<button>` at bottom of deep dive content |
| Background | `C.accent` |
| Text color | `#fff` |
| Font | 13px, weight 700 |
| Padding | `8px 16px` |
| Border radius | 8px |
| Margin top | 16px |
| Disabled state | `opacity: 0.5`, `cursor: default` when max depth reached |
| Max depth indicator | Show "Depth 2/3" text label (12px, `C.textMuted`) to the right of the button |

**Interaction:**
1. After first deep dive loads, "Go Deeper" button appears below content
2. Click triggers another Claude API call with accumulated context
3. New content appends below previous content with a `1px solid C.borderLight` separator
4. Button shows depth counter ("Depth 2/3")
5. At max depth (3), button disabled with reduced opacity

### 3. Promise Tracker Section (New FullStory section)

**Layout:** Renders as 7th section in FullStory SECTION_DEFS, following the same card pattern as other sections.

#### 3a. Section Header

Same pattern as SectionRenderer/ChecklistRenderer:
- Section number circle (24px, `C.badge` background)
- Title: "Management Promise Tracker" (16px, weight 700)
- VerdictBadge for aggregate verdict
- ConfidenceBadge for aggregate confidence

#### 3b. Aggregate Header Bar

Follows ChecklistRenderer `computeBarSegments` pattern exactly:

| Property | Specification |
|----------|---------------|
| Bar height | 8px |
| Bar border radius | 4px |
| Track background | `C.borderLight` |
| Segments | Green (KEPT), Yellow (PARTIAL), Red (BROKEN), `C.badge` (PENDING) |
| Segment proportions | Flex-based, proportional to count |
| Score text | 12px, weight 700, `C.textSecondary` |
| Score format | `{n} KEPT . {n} PARTIAL . {n} BROKEN` (middot separator) |
| Margin bottom | 16px |

#### 3c. Timeline Cards

Each promise renders as a timeline card. Cards display in chronological order (oldest first).

| Property | Specification |
|----------|---------------|
| Card container | `border: 1px solid C.borderLight`, `borderRadius: 6px`, `padding: 8px 16px`, `marginBottom: 8px` |
| Quarter tag | 12px, weight 700, `C.textMuted` (e.g., "Q3 2024") |
| Category badge | 10px, weight 700, uppercase, `C.badge` bg, `C.badgeText` color, `padding: 2px 8px`, `borderRadius: 4px`. Exception: 2px vertical padding per Spacing Exceptions table. |
| Status badge | Pill badge matching VerdictBadge pattern: `padding: 3px 10px`, `borderRadius: 9999`, `fontSize: 11`, `fontWeight: 700`, uppercase. Colors per status table above. Exception: 3px/10px per Spacing Exceptions table. |
| Quote text | 13px, weight 400, `C.text`, `lineHeight: 1.7`, `fontStyle: italic` |
| Expand/collapse | Chevron icon (11px, `C.textMuted`, rotates 90deg on expand). Same pattern as ChecklistRenderer items. |
| Expanded evidence | 13px, `C.textSecondary`, `lineHeight: 1.7`, `paddingLeft: 20px`, `paddingTop: 8px`. Shows "What they said" vs "What happened" comparison. |

**Card layout (collapsed):**
```
[Q3 2024] [Revenue Growth]          [KEPT]  >
"We expect to deliver 15% revenue growth..."
```

**Card layout (expanded):**
```
[Q3 2024] [Revenue Growth]          [KEPT]  v
"We expect to deliver 15% revenue growth..."
  What they said: Revenue growth of 15% in FY2025
  What happened: Achieved 17.2% revenue growth in FY2025
```

**Interaction:**
1. Click card row to expand/collapse evidence
2. Keyboard accessible: Enter/Space toggles
3. Multiple cards can be expanded simultaneously (independent state per card)

#### 3d. Empty State

| Property | Specification |
|----------|---------------|
| Container | `textAlign: 'center'`, `padding: '32px 0'` |
| Heading | 13px, weight 700, `C.textMuted` |
| Heading copy | "No Promises Tracked" |
| Body | 13px, weight 400, `C.textMuted` |
| Body copy | "Management promise data has not been generated for this report." |

### 4. Glossary — Dashed Underline Terms (SectionRenderer enhancement)

**Trigger:** Terms from `glossaryTerms[]` array per section. Pipeline marks which terms to highlight.

| Property | Specification |
|----------|---------------|
| Element | `<span>` wrapping the glossary term text within narrative |
| Text decoration | `text-decoration: underline`, `text-decoration-style: dashed`, `text-underline-offset: 3px` |
| Text decoration color | `C.accent` at 40% opacity (light mode: `rgba(15, 118, 110, 0.4)`, dark mode: `rgba(45, 212, 191, 0.4)`) |
| Cursor | `help` (indicates information available) |
| Hover | Decoration opacity increases to 80%, slight background tint `C.accentLight` |
| Click | Opens IndustryCard popover (existing component) positioned below the term |

**Density limit:** Maximum 3 glossary terms per paragraph to avoid visual noise. If pipeline provides more, render only the first 3 per paragraph block.

**Interaction:**
1. User reads narrative and notices dashed-underline terms (ambient, not distracting)
2. Hover shows increased underline opacity + subtle background
3. Click opens IndustryCard popover below the term
4. Click-outside or clicking another term closes the current popover
5. Only one IndustryCard open at a time

## Interaction Contracts

### Deep Dive Flow

```
Narrative text -> "Tell me more" link -> DeepDivePanel opens (right slide-out)
  -> Loading spinner (3-5s) -> Content renders
  -> "Go Deeper" button -> Loading -> Appended content (separator line)
  -> Depth 3 reached -> Button disabled
  -> Close (Escape / click overlay / X button) -> Content persisted in report JSON
```

### Promise Tracker Flow

```
Full Story section nav -> Click "Promise Tracker" -> Scroll to section
  -> View aggregate bar (KEPT/PARTIAL/BROKEN proportions)
  -> Click timeline card -> Expand evidence (what said vs what happened)
  -> Click again -> Collapse
  -> Keyboard: Enter/Space toggles expand
```

### Glossary Flow

```
Narrative text -> Dashed-underline term -> Hover (underline darkens)
  -> Click -> IndustryCard popover below term
  -> Read definition + benchmarks
  -> Click-outside -> Popover closes
  -> Click another term -> Previous closes, new opens
```

### State Management

| Feature | State Location | Persistence |
|---------|---------------|-------------|
| Deep dive content | Report JSON (`notableClaims[].deepDives[]`) | Permanent (IndexedDB via updateReport) |
| Deep dive panel open/close | Component useState | Session only |
| Deep dive loading | Component useState | Session only |
| Promise tracker expand/collapse | Component useState (Set) | Session only |
| Glossary popover open/close | Component useState | Session only |
| Glossary popover position | Computed from click target getBoundingClientRect | Transient |
