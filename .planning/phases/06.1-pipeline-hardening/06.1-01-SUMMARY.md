## Decisions Made
- Used fetch interceptor pattern rather than modifying engines -- intercepts both Vite middleware URLs (/api/yahoo-summary/, /api/yahoo-quotes/, /api/finviz/) and Yahoo v10 production URLs
- Created full IDB class stubs (IDBRequest, IDBDatabase, IDBObjectStore, IDBIndex, IDBCursor, IDBTransaction, IDBKeyRange) because the idb package does `instanceof` checks against these globals
- Added 30-second timeout wrapper to yahoo-finance2 calls because the library can hang indefinitely during crumb/cookie auth
- Used existing `fetchFilings` from edgar.js rather than writing new filing fetcher (code reuse)
- Added Thes1s taxonomy classification to DataPacket classification object so peers.js can find industry peers

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] fetchInsidersForTicker destructured wrong shape**
- **Found during:** Task 2 (verification)
- **Issue:** `fetchInsiderTransactions` returns `{ transactions, summary, ... }` object, not an array. Code called `.filter()` on the object.
- **Fix:** Destructure `.transactions` from result, use `.summary` directly
- **Files modified:** src/engines/dataExport.js
- **Verification:** COST assembly returns populated insiders field
- **Committed in:** 63f96fd

**2. [Rule 3 - Blocking] hydrateFromIDB bypassed IS_NODE routing**
- **Found during:** Task 2 (verification)
- **Issue:** `hydrateFromIDB` in cache.js called `idbBulkGet` directly, bypassing the IS_NODE early returns. Guru data loading crashed on IndexedDB.
- **Fix:** Added IS_NODE branch to `hydrateFromIDB` that reads from file cache
- **Files modified:** src/engines/cache.js
- **Committed in:** 63f96fd

**3. [Rule 3 - Blocking] IDB class globals not defined**
- **Found during:** Task 2 (verification)
- **Issue:** The `idb` package references `IDBRequest`, `IDBDatabase`, `IDBObjectStore`, `IDBIndex`, `IDBCursor`, `IDBTransaction` as globals for `instanceof` checks. Missing globals caused crashes or hanging promises.
- **Fix:** Defined all IDB class stubs globally with `addEventListener` support so `idb`'s `promisifyRequest` works correctly
- **Files modified:** src/engines/nodeAdapter.js
- **Committed in:** c026a09

**4. [Rule 3 - Blocking] Yahoo v10 production URL not intercepted**
- **Found during:** Task 2 (verification)
- **Issue:** `analystEstimates.js` in non-dev mode fetches `https://query1.finance.yahoo.com/v10/finance/quoteSummary/...` which needs crumb auth. Our interceptor only handled `/api/yahoo-summary/` (dev path).
- **Fix:** Added regex match for Yahoo v10 quoteSummary URLs in the fetch interceptor
- **Files modified:** src/engines/nodeAdapter.js
- **Committed in:** 63f96fd

**5. [Rule 3 - Blocking] Peers returned empty due to missing Thes1s classification**
- **Found during:** Task 2 (verification)
- **Issue:** `dataExport.js` passed `{ industryType, sicCode, sicDescription }` to `fetchPeersByTier`, but `peers.js` expects `{ sector, industryGroup, industry }` from the Thes1s taxonomy.
- **Fix:** Added `classifyCompany` call from `thes1sClassification.js` and included taxonomy fields in classification object
- **Files modified:** src/engines/dataExport.js
- **Committed in:** 63f96fd

**6. [Rule 3 - Blocking] yahoo-finance2 calls hang indefinitely**
- **Found during:** Task 2 (verification)
- **Issue:** Yahoo Finance API calls via yahoo-finance2 package can hang during crumb/cookie authentication, causing DataPacket assembly to never complete
- **Fix:** Added `withTimeout()` wrapper (30s) around all yahoo-finance2 calls in nodeYahoo.js
- **Files modified:** src/engines/nodeYahoo.js
- **Committed in:** c026a09
