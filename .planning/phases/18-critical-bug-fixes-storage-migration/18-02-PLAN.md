<objective>
Migrate report storage from localStorage to IndexedDB so users can store 20+ company reports without hitting browser storage limits. Auto-migrate existing data seamlessly.

Purpose: localStorage has a ~5MB limit. A single Pitch Deck report is ~400KB JSON. At 6-7 companies, localStorage fills up and saves fail silently. IndexedDB has no practical limit (hundreds of MB).

Output: Reports stored in IndexedDB, auto-migration from localStorage, async loading with skeleton UI, identical CRUD API.
</objective>

**Part A: Update cacheStore.js per D-01 and D-03**

1. Bump `DB_VERSION` from 5 to 6.

2. Add `'reports'` to the STORES array:
```js
const STORES = ['edgar-facts', 'edgar-statements', 'guru-data', 'nport-data', 'filing-markdown', 'insider-data', 'comp-data', 'transcript-data', 'reports'];
```

3. The existing upgrade handler already creates any missing stores:
```js
upgrade(db) {
  for (const store of STORES) {
    if (!db.objectStoreNames.contains(store)) {
      db.createObjectStore(store, { keyPath: 'key' });
    }
  }
}
```
This will automatically create the 'reports' store on version bump. No additional index needed (Claude's discretion: simple key-based lookup is sufficient for single-user app with <100 reports).

4. Add two new exported helpers for the reports store specifically (reports don't use TTL — they're permanent until deleted):

```js
// Get all reports from the 'reports' store (no TTL check — reports are permanent)
export async function idbGetAll(store) {
  const db = await getDB();
  if (!db) return [];
  try {
    const all = await db.getAll(store);
    return all.map(record => record.data);
  } catch {
    return [];
  }
}

// Delete a record from a store by key
export async function idbDelete(store, key) {
  const db = await getDB();
  if (!db) return;
  try {
    await db.delete(store, key);
  } catch {
    // Ignore delete errors
  }
}
```

Also add an overload of `idbSet` for reports that doesn't require TTL — or simply use a very long TTL (10 years = 315360000000 ms). The existing `idbSet` with TTL works fine; use `const REPORT_TTL = 10 * 365 * 24 * 60 * 60 * 1000;` as a constant in useResearch.js.

**Part B: Rewrite useResearch.js for async IndexedDB per D-02**

The hook must maintain the exact same external API: `{ reports, createReport, updateReport, deleteReport, getReport }`. But internally it switches from sync localStorage to async IndexedDB.

Key changes:

1. Add imports at top:
```js
import { idbGet, idbSet, idbDelete, idbGetAll } from '../engines/cacheStore';
```

2. Add constants:
```js
const STORAGE_KEY = 'stock-analyzer-reports';  // Keep for migration
const IDB_STORE = 'reports';
const IDB_INDEX_KEY = '__report_index__';  // Special key to store the report ID list
const REPORT_TTL = 10 * 365 * 24 * 60 * 60 * 1000;  // 10 years (effectively permanent)
```

3. Replace sync `loadReports` with async loading pattern:
   - Use `useState` for `reports` (initialized to `[]`), `loading` (initialized to `true`), `error` (initialized to `null`)
   - On mount (useEffect), load from IndexedDB:
     a. Try `idbGetAll('reports')` to get all reports
     b. If empty, check localStorage for migration per D-02:
        - Read `localStorage.getItem('stock-analyzer-reports')`
        - If data exists, parse it, write each report to IndexedDB via `idbSet('reports', report.id, report, REPORT_TTL)`
        - Then remove from localStorage: `localStorage.removeItem('stock-analyzer-reports')`
        - Console.log migration: `console.log('Migrated ${count} reports from localStorage to IndexedDB')`
     c. Set `reports` state, set `loading` to false
   - Handle errors: catch block sets `error`, sets `loading` false, falls back to empty array

4. Replace sync `saveReports` with async per-report saves:
   - `createReport`: generate report object, call `idbSet('reports', newReport.id, newReport, REPORT_TTL)`, update state
   - `updateReport(id, updates)`: merge updates into existing report, call `idbSet('reports', id, mergedReport, REPORT_TTL)`, update state
   - `deleteReport(id)`: call `idbDelete('reports', id)`, update state
   - `getReport(id)`: same as before (reads from in-memory state)

5. Remove the `evictCaches` function and the QuotaExceededError handling — IndexedDB doesn't have the same limits.

6. The async save operations should be fire-and-forget (don't await in the state setter). Pattern:
```js
const createReport = useCallback((ticker, companyName = '') => {
  const now = new Date().toISOString().slice(0, 10);
  const newReport = {
    id: uuidv4(),
    ticker: ticker.toUpperCase(),
    companyName,
    createdAt: now,
    updatedAt: now,
    currentStage: 1,
    stageApprovals: { onePager: null, pitchDeck: null, fullStory: null },
    onePager: {},
    pitchDeck: null,
    fullStory: null,
    notes: '',
    watchlist: false,
    competitors: { privateCompetitors: [] },
  };
  setReports(prev => [newReport, ...prev]);
  idbSet(IDB_STORE, newReport.id, newReport, REPORT_TTL).catch(err =>
    console.warn('Failed to save report to IndexedDB:', err.message)
  );
  return newReport;
}, []);
```

7. Add `loading` to the return value: `return { reports, loading, createReport, updateReport, deleteReport, getReport };`

8. In App.jsx, the `loading` value from useResearch is available but not required to use yet — per D-09, skeleton screens will be handled by individual report components. The important thing is that `reports` starts as `[]` and fills asynchronously, which means consumers that iterate over `reports` (like ReportsList) will naturally show empty then populate — this is acceptable. If a consumer needs loading state, they can check `loading`.
