# Phase 24 — UI Design Contract

> Visual and interaction contract for PM Workflow Controls. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none (inline styles via mutable `C` palette) |
| Icon library | Inline SVG (hand-drawn, 12-24px viewBox, stroke-based, 2px stroke) |
| Font | Inter / system font stack (`-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, ...`) |

**Source:** Established project convention (theme.js, all existing components). No shadcn, no Tailwind, no CSS files. All styling is inline via `import { C } from '../theme'`.

---

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline badge padding, label margins |
| sm | 8px | Compact element spacing, gap between badges |
| md | 16px | Default element spacing, card padding, section margins |
| lg | 24px | Section padding, major content gaps |
| xl | 32px | Layout gaps between major panels |
| 2xl | 48px | Not used in this phase |
| 3xl | 64px | Not used in this phase |

Exceptions:
- Section card padding: `16px 20px` (established SectionRenderer pattern -- 16px vertical, 20px horizontal)
- Approval bar padding: `16px 20px` (established OnePager pattern)
- Table cell padding: `10px 14px` (established ResearchList pattern)
- Comment box internal padding: `12px 16px` (consistent with summary callout pattern)

**Source:** Existing SectionRenderer.jsx (line 98), OnePager.jsx (line 389), ResearchList.jsx (line 94).

## Typography

| Role | Size | Weight | Line Height | Usage in Phase 24 |
|------|------|--------|-------------|-------------------|
| Body | 13px | 400 | 1.5-1.7 | Comment text, data gap descriptions, dialog body copy |
| Label | 11px | 600 | 1.3 | Column headers, badge labels, uppercase meta text (`letterSpacing: 0.04em`, `textTransform: uppercase`) |
| Heading | 16px | 600 | 1.2 | Section titles, panel titles, checkpoint panel header, empty state heading, dialog title |
| Display | 18px | 600 | 1.2 | Page-level headings (e.g., "Checkpoint Review") |

**Source:** Existing codebase conventions. 13px body (CLAUDE.md), 11px labels (CompanyHeader line 19, ResearchList line 97), 16px section titles (SectionRenderer line 131), 18px page headings (ResearchList line 76). Weights collapsed to 400 (body) + 600 (emphasis) per checker feedback.

## Color

| Role | Value (Light / Dark) | Usage |
|------|---------------------|-------|
| Dominant (60%) | `#f8f9fb` / `#0f172a` | Page background (`C.bg`) |
| Secondary (30%) | `#ffffff` / `#1e293b` | Cards, panels, checkpoint panel background (`C.bgCard`) |
| Accent (10%) | `#0f766e` / `#2dd4bf` | See reserved-for list below (`C.accent`) |
| Destructive | `#dc2626` / `#f87171` | Re-run Wave confirmation, delete actions (`C.red`) |
| Success | `#16a34a` / `#4ade80` | Continue button, completion banners, PASS badges (`C.green`) |
| Warning | `#ca8a04` / `#fbbf24` | High-severity data gap dots, PARTIAL badges (`C.yellow`) |

**Accent reserved for:**
1. "Generate One Pager" / "Generate Pitch Deck" / "Generate Full Story" button background
2. "View One Pager" / "View Pitch Deck" / "View Full Story" button text
3. Ticker text in CompanyHeader and ResearchList rows
4. Comment icon badge count indicator
5. Data gap "Add source" link text
6. "View Reports" / "View Toolbox" cross-navigation link text

**Accent is NOT used for:** Continue/Re-run action buttons (those use `C.green` and `C.red + border` respectively), approval bar buttons (established green/red pattern), or severity dots (those use semantic red/yellow/green).

**Source:** theme.js (C_LIGHT, C_DARK), VerdictBadge.jsx, OnePager.jsx approval bar.

## Interaction Contracts

### IC-01: Checkpoint Panel Display

**Trigger:** `progress.state` matches `/^CHECKPOINT_\d+$/`
**Behavior:** CheckpointPanel renders in place of the generation-in-progress view. Displays:
1. Data gaps section (top, always visible if gaps exist)
2. Completed section cards (each with SectionRenderer + comment icon in header)
3. Action bar at bottom (Continue + Re-run Wave buttons)

**Layout:**
```
+--------------------------------------------------+
| CHECKPOINT REVIEW - Wave {N}                      |
| {elapsed time} | {completed}/{total} sections     |
+--------------------------------------------------+
|                                                    |
| DATA GAPS ({count})                     [collapse] |
| +----------------------------------------------+  |
| | (red dot) API failure: Finnhub...  [Add src]  |  |
| | (yellow dot) Missing: Analyst...   [Add src]  |  |
| +----------------------------------------------+  |
|                                                    |
| COMPLETED SECTIONS                                 |
| +----------------------------------------------+  |
| | 1  Radar          PASS  HIGH  (comment icon)  |  |
| |    [section narrative content...]              |  |
| +----------------------------------------------+  |
| +----------------------------------------------+  |
| | 2  Simple & Predictable  PASS  (comment icon) |  |
| |    [section narrative content...]              |  |
| +----------------------------------------------+  |
|                                                    |
| +----------------------------------------------+  |
| |              [Continue]  [Re-run Wave]         |  |
| +----------------------------------------------+  |
+--------------------------------------------------+
```

**States:**
- Default: Data gaps collapsed if empty, expanded if non-empty. Sections expanded.
- Loading: Spinner centered in panel while checkpoint data loads.
- No data gaps: Data gaps section hidden entirely.

### IC-02: Toggle-to-Show Comment Box

**Trigger:** Click on comment icon button in SectionRenderer header
**Behavior:** Comment area slides open below the section header (above narrative content). Uses CollapsibleSection animation pattern (scrollHeight measurement + 280ms CSS transition).

**Comment icon button spec:**
- SVG: 14px chat-bubble icon, stroke-based, 2px stroke
- Color: `C.textMuted` when no comments, `C.accent` when comments exist
- `aria-label="Toggle section comments"`
- Badge: If `commentCount > 0`, show count in a 16px circle badge (background `C.accent`, color `#fff`, fontSize 10px, fontWeight 600) positioned top-right of icon (-4px offset)
- Click area: 28px square minimum touch target

**Expanded comment area spec:**
```
+----------------------------------------------+
| [textarea: 3 rows, auto-grow, max 8 rows]    |
|                                               |
| Attachments: earnings.pdf (245KB) [x]         |
|              tam-chart.png (120KB) [x]        |
|                                               |
| [Attach File]                  [Save Comment] |
+----------------------------------------------+
```

**Textarea:** Background `C.bgInput`, border `1px solid ${C.border}`, borderRadius 6px, padding `8px 12px`, fontSize 13px, color `C.text`, placeholder color `C.textMuted`, focus border `C.accent`.

**Attach File button:** Ghost button (transparent background, `1px solid ${C.border}`, borderRadius 6px, fontSize 11px, fontWeight 600, color `C.textSecondary`). Native `<input type="file" multiple accept=".pdf,.png,.jpg,.jpeg,.doc,.docx,.xlsx">` hidden behind it.

**Save Comment button:** Primary button (background `C.accent`, color `#fff`, borderRadius 6px, padding `8px 16px`, fontSize 11px, fontWeight 600).

**File attachment chips:**
- Background: `C.badge`, borderRadius 4px, padding `4px 8px`
- Text: fontSize 11px, color `C.text`, fontWeight 400
- Size label: fontSize 10px, color `C.textMuted`
- Remove [x]: 14px, color `C.textMuted`, hover `C.red`, cursor pointer

**File size limit:** 10MB per file. Total 50MB per checkpoint. Show inline error `C.red` if exceeded: "File exceeds 10MB limit"

### IC-03: Data Gap Actions

**Trigger:** Click "Add source" on a data gap item
**Behavior:** Expands inline form below the gap item with two options:

```
+----------------------------------------------+
| (red dot) API failure: Finnhub transcripts    |
|   not available (free tier)                   |
|                                               |
|   Paste URL: [________________________]       |
|   -- or --                                    |
|   [Attach File]                               |
|                                  [Save]       |
+----------------------------------------------+
```

**Severity dots:**
- High (`C.red`): 8px filled circle, API failures, critical missing data
- Medium (`C.yellow`): 8px filled circle, degraded data quality
- Low (`C.green`): 8px filled circle, nice-to-have data

**URL input:** Same styling as comment textarea but single line. Placeholder: "Paste URL to data source..."

### IC-04: Checkpoint Action Buttons

**Continue button:**
- Background: `C.green`, color `#fff`
- Padding: `8px 24px`, borderRadius 6px
- FontSize: 13px, fontWeight 600
- Hover: opacity 0.9
- Label: "Continue to Wave {N+1}" or "Continue to Completion" (last wave)

**Re-run Wave button:**
- Background: transparent, color `C.red`, border `1px solid ${C.red}`
- Padding: `8px 24px`, borderRadius 6px
- FontSize: 13px, fontWeight 600
- Hover: background `C.redBg`
- Label: "Re-run Wave {N}"

**Action bar layout:** Right-aligned, 12px gap between buttons. Matches existing approval bar pattern from OnePager.jsx.

**On Continue:** POST checkpoint feedback to disk endpoint, advance progress state, resume polling.
**On Re-run:** POST checkpoint feedback (comments + attachments + filled data gaps), signal pipeline to re-run wave with PM feedback, resume polling.

### IC-05: Contextual Generate Button

**Placement:** Rendered by Toolbox.jsx in the CompanyHeader area, between the company info (left) and score badges (right). Vertically centered.

**Button states and labels:**

| State | Label | Style | Action |
|-------|-------|-------|--------|
| No One Pager exists | "Generate One Pager" | Primary (bg `C.accent`, color `#fff`) | Open ConfirmGenerateDialog |
| OP generated, not approved | "View One Pager" | Ghost (border `C.accent`, color `C.accent`) | Navigate to `/reports/{ticker}/one-pager` |
| OP approved, no PD | "Generate Pitch Deck" | Primary (bg `C.accent`, color `#fff`) | Open ConfirmGenerateDialog |
| PD generated, not approved | "View Pitch Deck" | Ghost (border `C.accent`, color `C.accent`) | Navigate to `/reports/{ticker}/pitch-deck` |
| PD approved, no FS | "Generate Full Story" | Primary (bg `C.accent`, color `#fff`) | Open ConfirmGenerateDialog |
| FS generated, not approved | "View Full Story" | Ghost (border `C.accent`, color `C.accent`) | Navigate to `/reports/{ticker}/full-story` |
| FS approved | "View Full Story" | Ghost (border `C.accent`, color `#fff`) | Navigate to `/reports/{ticker}/full-story` |
| Generation in progress | "Generating..." | Disabled (bg `C.badge`, color `C.badgeText`) | None (shows spinner) |

**Primary button spec:** Background `C.accent`, color `#fff`, padding `8px 20px`, borderRadius 6px, fontSize 13px, fontWeight 600, cursor pointer. Hover: `C.accentHover`.

**Ghost button spec:** Background transparent, border `1px solid ${C.accent}`, color `C.accent`, padding `8px 20px`, borderRadius 6px, fontSize 13px, fontWeight 600. Hover: background `C.accentLight`.

**Disabled button spec:** Background `C.badge`, color `C.badgeText`, border none, cursor default, opacity 0.7. Inline Spinner (12px) to left of text.

### IC-06: Confirmation Dialog

**Trigger:** Click "Generate {Stage}" button
**Behavior:** Overlay modal (same pattern as DeepDivePanel overlay: `position: fixed, inset: 0, background: rgba(0,0,0,0.3), zIndex: 1000`). Dialog centered on screen.

**Dialog layout:**
```
+------------------------------------------+
|  Generate One Pager for COST              |
|                                           |
|  This kicks off an AI research pipeline   |
|  that takes ~5-10 minutes and costs       |
|  ~$2-3. The One Pager is a screening      |
|  filter -- only generate for companies    |
|  you're seriously considering.            |
|                                           |
|  You are beginning a 3-stage research     |
|  process (One Pager -> Pitch Deck ->      |
|  Full Story). The whole pipeline takes     |
|  much longer -- by design.               |
|                                           |
|       [Never Mind]  [Generate One Pager]  |
+------------------------------------------+
```

**Dialog container:**
- Background: `C.bgCard`
- Border: `1px solid ${C.border}`
- BorderRadius: 12px
- Padding: 24px
- Width: 440px (matches DeepDivePanel width convention)
- BoxShadow: `0 8px 32px rgba(0,0,0,0.15)`
- Position: fixed, top 50%, left 50%, transform translate(-50%, -50%), zIndex 1001

**Dialog title:** fontSize 16px, fontWeight 600, color `C.text`, marginBottom 16px.

**Dialog body:** fontSize 13px, color `C.textSecondary`, lineHeight 1.6.

**Stage-specific copy:**

| Stage | Title | Estimate | Extra context |
|-------|-------|----------|---------------|
| One Pager | "Generate One Pager for {TICKER}" | "~5-10 minutes, ~$2-3" | "You are beginning a 3-stage research process (One Pager, Pitch Deck, Full Story). The whole pipeline takes much longer -- by design." |
| Pitch Deck | "Generate Pitch Deck for {TICKER}" | "~15-25 minutes, ~$4-6" | "This is a deep 10-section business analysis. You will review at checkpoints between each wave." |
| Full Story | "Generate Full Story for {TICKER}" | "~10-15 minutes, ~$3-4" | "This is the final conviction gate. Includes checklists, adversarial debate, and valuation confirmation." |

**Never Mind button:** Ghost style (transparent background, `1px solid ${C.border}`, color `C.textSecondary`, borderRadius 6px, padding `8px 20px`, fontSize 13px, fontWeight 600).

**Generate button (stage-specific label):** Label is "Generate One Pager" / "Generate Pitch Deck" / "Generate Full Story" matching the stage. Primary accent style (background `C.accent`, color `#fff`, borderRadius 6px, padding `8px 20px`, fontSize 13px, fontWeight 600). Hover: `C.accentHover`.

**Close behavior:** Escape key, overlay click, or Never Mind button. Same pattern as DeepDivePanel.

### IC-07: Cross-Navigation Buttons

**ResearchList "View Reports" button:**
- Placement: In the action column (before the Delete button), same row
- Style: Ghost button (transparent background, `1px solid ${C.border}`, borderRadius 6px, padding `4px 8px`, fontSize 11px, fontWeight 600, color `C.accent`)
- Hover: background `C.accentLight`, borderColor `C.accent`
- Action: `navigate('/reports')` (navigates to Reports tab; user scans for ticker)
- Always visible: Show for all research rows regardless of report existence. If no reports exist for that ticker, user sees the Reports empty state.

**ReportsList "View Toolbox" link:**
- Placement: Below ticker name in each report card, inline link style
- Style: fontSize 12px, color `C.accent`, textDecoration underline on hover, cursor pointer
- Action: Navigate to `/research/{reportId}` for that ticker
- Only visible when a matching research report exists (use `findReport(ticker)`)

## State Catalog

### Checkpoint Panel States

| State | Visual Treatment |
|-------|-----------------|
| Loading | Spinner centered in checkpoint panel card, "Loading checkpoint..." text below |
| Data gaps present | DataGapsPanel expanded at top, yellow/red severity dots |
| No data gaps | DataGapsPanel section hidden (not collapsed -- completely absent) |
| Comments exist on section | Comment icon shows accent color + count badge |
| No comments on section | Comment icon shows muted color, no badge |
| Comment box open | Slide-open animation (280ms), textarea focused |
| Comment box closed | Height 0, overflow hidden |
| File attached | Chip with filename + size + remove [x] |
| File upload error | Inline red text below attach button |
| Continue clicked | Button disabled + spinner, "Advancing..." label |
| Re-run clicked | Inline confirmation: "Re-run Wave {N}" (confirm button) / "Keep Current" (dismiss button) |

### Generate Button States

| State | Label | Enabled | Style |
|-------|-------|---------|-------|
| Ready to generate | "Generate {Stage}" | Yes | Primary accent |
| Report exists, not approved | "View {Stage}" | Yes | Ghost accent |
| Report approved, next unlocked | "Generate {NextStage}" | Yes | Primary accent |
| All stages complete | "View Full Story" | Yes | Ghost accent |
| Generation in progress | "Generating..." | No | Disabled with spinner |

### Confirmation Dialog States

| State | Visual Treatment |
|-------|-----------------|
| Open | Overlay + centered dialog, "Generate {Stage}" button enabled, "Never Mind" button enabled |
| Generating (after confirm) | "Generate {Stage}" button disabled + spinner, "Starting pipeline..." label, dialog remains open until POST returns |
| Error | Red text below dialog body: "Failed to start generation. {error message}" |
| Success | Dialog closes, GenerateButton transitions to "Generating..." disabled state |
