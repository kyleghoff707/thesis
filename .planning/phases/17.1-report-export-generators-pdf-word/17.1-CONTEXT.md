# Phase 17.1: Report Export Generators (PDF + Word) - Context

**Gathered:** 2026-04-01
**Status:** Ready for planning
**Source:** Conversation context (discovered during Phase 17 execution)

<domain>
## Phase Boundary

Generic, ticker-agnostic export generators for all 3 pipeline stages (One Pager, Pitch Deck, Full Story). Refactors existing PDF scripts from hardcoded single-ticker to parameterized. Adds Full Story PDF generator (doesn't exist yet). Adds Word doc (.docx) generators for all 3 stages. Produces MNST exports as validation proof.

**Why this exists:** During Phase 17 end-to-end validation, we discovered the existing PDF generators are hardcoded to specific tickers (CEG for One Pager, SFM for Pitch Deck) and can't generate PDFs from the new pipeline output. No Full Story PDF generator exists at all. No Word doc generators exist. Users need to be able to export research reports as PDFs and Word docs.

</domain>

<decisions>
## Implementation Decisions

### Existing Code State
- `scripts/pdf/generate_one_pager_pdf.py` (801 lines) — hardcoded for CEG, function is `generate_ceg_one_pager()`, reads from `.thes1s/reports/CEG/`
- `scripts/pdf/generate_pitch_deck_pdf.py` (951 lines) — takes ticker as arg but reads `pitch-deck.json` (pipeline outputs `pipeline-output.json`), expects `overallVerdict` at top level
- `scripts/pdf/pdf_template_toolkit.py` (874 lines) — shared ReportPDF base class, Thes1s branding, chart methods
- No Full Story PDF generator exists
- No Word doc generators exist for any stage

### Pipeline Output Format (what generators must consume)
- One Pager: `.thes1s/reports/{TICKER}/one-pager.json` — keys: ticker, companyName, stage, generatedAt, sections, overallVerdict, sectionKeys. Section keys: company_info, minimum_standards, meaning, growth_metrics, valuation_summary, overall_verdict
- Pitch Deck: `.thes1s/reports/{TICKER}/pipeline-output.json` — keys: ticker, stage, completedAt, sectionCount, errorCount, sections, budget, cacheStats, errors. Section keys: radar, simple_and_predictable, market_position, barriers_and_moats, fcf, management, balance_sheet, pest_risks, valuation_summary, overall_verdict. Each section has: key, title, sectionNumber, status, confidence, verdict, verdictRationale, summary, data, narrative, citations, tables, charts, redFlags, primarySourceInsights, crossCuttingFindings, modelUsed, tokenCost
- Full Story: `.thes1s/reports/{TICKER}/full-story-api.json` — same section schema as PD. Section keys: event_analysis, meaning_checklist, moat_checklist, management_checklist, valuation_confirmation, inversion_rebuttal. Also has debateOutputs.
- DataPacket: `.thes1s/reports/{TICKER}/data-packet.json` — shared financial data (exists for all tickers)
- Quality: `.thes1s/reports/{TICKER}/quality/{stage}-v4.quality.json` and `.md`

### Requirements
- All generators must be ticker-agnostic (take ticker as CLI argument)
- All generators must read from the pipeline output format (not hardcoded JSON structures)
- Backward compatibility: existing CEG/SFM outputs should still work if their JSON structure matches
- PDF generators use the existing pdf_template_toolkit.py ReportPDF base class and Thes1s branding
- Word doc generators should produce professional .docx files with similar content/formatting
- MNST must be the validation proof — generate all 6 outputs (3 PDFs + 3 Word docs)

### Claude's Discretion
- Whether to refactor existing generators in-place or create new generic ones
- Word doc library choice (python-docx is the standard)
- How to handle the One Pager's simpler structure vs PD/FS's richer ReportSectionSchema
- Chart rendering strategy for Word docs (embed as images, or skip charts in Word)
- Whether to share rendering logic between PDF and Word or keep them independent

</decisions>

<specifics>
## Specific Ideas

- The One Pager PDF is simpler (6 sections, pass/fail verdict) — good candidate for first implementation
- Pitch Deck has 10 sections with charts, tables, citations — most complex
- Full Story has 6 sections including checklists and an adversarial debate — unique rendering challenges
- Word docs could be simpler than PDFs (no custom chart rendering needed, just formatted text + tables)
- Consider a shared "section renderer" abstraction that both PDF and Word generators call

</specifics>
