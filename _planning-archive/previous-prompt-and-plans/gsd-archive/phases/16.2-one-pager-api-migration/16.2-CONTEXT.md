<domain>
## Phase Boundary

Migrate the One Pager from CC skill execution (`generate-one-pager` skill) to Claude API dispatch using the same `aiResearch.js` / `pipelineManager.js` infrastructure proven on Pitch Deck (Phase 10) and Full Story (Phase 16). This completes the CC-to-API migration across all 3 stages.

Phase 16.1 already simplified the One Pager to a single Sonnet call (`onePagerGenerator.js`). This phase wires that generator into the existing API dispatch infrastructure so all 3 stages use the same execution path — `run-pipeline.js` → `pipelineManager.js` → `aiResearch.js`.

**What exists (from Phase 16.1):**
- `src/engines/onePagerGenerator.js` — Single Sonnet call, produces 6-section structured output
- `src/schemas/onePagerOutput.js` — Zod schema for structured output
- `scripts/run-pipeline.js` — Has early-exit branch for onePager that calls `generateOnePager` directly
- `agents/orchestrator/dispatch-table.json` — onePager entry has `mode: "single-call"`, sectionKeys preserved
- `.claude/skills/generate-one-pager/SKILL.md` — Simplified CC skill (77 lines)

**What exists (from Pitch Deck / Full Story API migration):**
- `src/engines/aiResearch.js` — `dispatchAgent()` for individual agent calls with structured output
- `src/engines/pipelineManager.js` — Wave-based parallel dispatch, cost tracking, cache monitoring
- `scripts/run-pipeline.js` — Full pipeline runner for pitchDeck and fullStory stages
- Quality scoring via `src/engines/critic.js`

<decisions>
## Implementation Decisions

### Migration Strategy
- Follow the exact same pattern as Pitch Deck (Phase 10) and Full Story (Phase 16) API migrations
- The One Pager is simpler — single call, no waves, no debate, no checkpoints
- Wire `onePagerGenerator.js` through `aiResearch.js` dispatch OR make `pipelineManager.js` handle the `mode: "single-call"` dispatch table entry
- The `run-pipeline.js` early-exit branch from Phase 16.1 should be replaced with the standard pipeline path (so all 3 stages go through the same code)

### What Must Work After Migration
- `node scripts/run-pipeline.js --ticker COST --stage onePager` produces the same output as before
- Cost tracking via budget tracker (already in aiResearch.js)
- Cache monitoring (already in pipelineManager.js)
- Output written to `.thes1s/reports/{TICKER}/one-pager.json` in backward-compatible format
- Gate check still works (overallVerdict field for Pitch Deck gate)

### CC Skill
- The CC skill can be deprecated or kept as a thin wrapper that calls the API path
- Primary execution path is now API (run-pipeline.js)

### Claude's Discretion
- Whether to route through pipelineManager.js (adding single-call support) or call aiResearch.js directly from run-pipeline.js
- Whether the dispatch table needs further updates
- How to handle quality scoring for the simplified one pager output

</decisions>
