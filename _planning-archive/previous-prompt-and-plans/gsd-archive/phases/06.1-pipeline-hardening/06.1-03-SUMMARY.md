## Decisions Made
- **Separate file for generation status:** generation-status.json is a separate pollable file from progress.json (the state machine). The state machine tracks generation orchestration; generation-status.json tracks per-section timing and overall progress for the UI component.
- **Deep-merge for status updates:** updateGenerationStatus deep-merges section and phase updates rather than replacing them, so callers only need to pass what changed.
- **Non-critical auto-wire:** advanceState updates generation-status.json inside a try/catch so state machine operations are never blocked by status file failures.
- **Filing pre-processing is optional:** Step 2.5 gracefully handles the case where filingSections.js is not yet available (Plan 06.1-02 dependency). The pipeline continues with agents fetching filings directly.
- **Single retry limit:** Per D-02-d, agents get exactly one retry after a 30-second wait. After that, the section is saved as "failed" and the PM can re-run via /generate:section. No infinite retry loops.
