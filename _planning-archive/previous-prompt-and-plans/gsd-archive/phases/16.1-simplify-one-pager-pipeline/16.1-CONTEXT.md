# Phase 16.1: Simplify One Pager Pipeline - Context

**Gathered:** 2026-04-01
**Status:** Ready for planning
**Source:** Direct user direction (conversation)

<domain>
## Phase Boundary

Strip the One Pager pipeline from a multi-agent parallel dispatch (4 agents, 6 sections, 2 waves) down to a single Claude API call. The One Pager is a quick filter — "should I spend 40 hours researching this company?" — not a deep analysis. The deep analysis belongs in the Pitch Deck and Full Story pipelines.

**Current state (to be replaced):**
- 4 AI agents: business-analyst, financial-analyst, valuation-specialist, synthesis-writer
- 6 sections dispatched via pipelineManager.js wave-based parallel execution
- Dispatch table entry in `agents/orchestrator/dispatch-table.json` with pre/post processing
- Full ReportSectionSchema structured output per section
- Cost: multiple Sonnet + Opus calls with prompt caching

**Target state:**
- 1 single Claude API call (Sonnet)
- Input: full DataPacket + curriculum (`one-pager.md`) + Buffett writing guide + template
- Output: filled-out one pager template — concise, fits conceptually on "one page"
- Runtime: ~2 minutes
- No multi-agent orchestration, no wave dispatch, no section-by-section generation

</domain>

<decisions>
## Implementation Decisions

### Pipeline Architecture
- Replace multi-agent dispatch with a single `dispatchAgent` call (or direct Claude API call via aiResearch.js)
- The one pager does NOT need pipelineManager.js — it's one call, not a pipeline
- Keep using the existing DataPacket from `dataExport.js` (no changes to data assembly)
- Keep the `run-pipeline.js` entry point working for `onePager` stage — it just calls one function instead of orchestrating waves

### Agent/Model Selection
- Use Sonnet (fast, cheap, sufficient for a screening pass)
- One agent gets ALL the data — no slicing by specialty
- Agent gets: full DataPacket, one-pager curriculum, Buffett writing guide, template

### Output Format
- Output should match the template structure from `knowledge/stage-1-one-pager/template.md`
- Keep structured output (ReportSectionSchema or similar) for machine-readable verdict (PASS/FAIL)
- But the narrative content should be concise — this is a one-page screening document, not a 10-page report

### What to Preserve
- DataPacket assembly (dataExport.js) — unchanged
- The one-pager template and curriculum files — unchanged
- The gate check (Pitch Deck requires One Pager PASS) — unchanged
- PDF generation script — may need minor updates if output structure changes
- Quality scoring in critic.js — simplify or skip for one pager (it's a filter, not a scored report)

### What to Remove/Simplify
- Remove one pager entries from dispatch-table.json (or replace with single-call config)
- Remove wave-based orchestration for one pager from pipelineManager.js
- The generate-one-pager CC skill can be greatly simplified or removed (API path is primary)
- One pager does NOT need per-section quality scoring — just a PASS/FAIL verdict

### Claude's Discretion
- Exact prompt construction (how to combine DataPacket + curriculum + template in one call)
- Whether to use existing `dispatchAgent` or a new simpler function
- How to handle the output schema (single ReportSectionSchema vs custom one-pager schema)
- Whether the CC skill needs updating or can be deprecated in favor of API-only

</decisions>
