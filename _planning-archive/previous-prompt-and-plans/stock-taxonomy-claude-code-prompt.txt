## CONTEXT

Thes1s is a Tauri + React desktop stock research app that benchmarks companies
against their peers using Rule One investing methodology. The Competitors tab
currently discovers peers via SEC SIC codes mapped through a hand-built ~250-code
classification file (sicClassification.js). SIC codes are unreliable — they were
designed in 1937, are self-reported, rarely updated, ignore multi-segment companies,
and have no categories for modern industries (SaaS, fintech, streaming, EVs, etc.).

The goal is to design and build a comprehensive custom industry classification
taxonomy covering the entire US public stock market (~6,000–8,000 actively traded
companies) that replaces or supplements the current SIC-based system. The taxonomy
must be derived programmatically using freely available data and must serve
Buffett-style fundamental research: grouping companies by who they actually compete
with for customers and revenue.

This prompt combines two skill workflows:
  1. RESEARCH DIVE — Deep investigation of how existing taxonomy systems work,
     their structures, update cadences, classification criteria, and how to
     build one from scratch using free data.
  2. COMPUTER LEARNING — Teaching Claude to interpret and classify companies
     into the taxonomy so it can be maintained and extended by agents.


## RESEARCH SCOPE (from user)

"We need to build a full on market-wide sector, industry, and industry grouping
taxonomy map across the entire stock market. Companies like Morningstar, Yahoo
Finance, Bloomberg, etc already do this in the background when you select a given
company and look at its peers. I just want to build it out myself. The idea is
we'll have an internal file that will map out every single company in the entire
stock market, which sector they belong in, which industry they belong in, what
sub industry group they belong in, so that the software can rely on this instead
of (or in addition to) the SIC mapping that we are currently using."

Key questions to answer:
  1. How do Morningstar, GICS (S&P/MSCI), ICB (FTSE Russell), Bloomberg (BICS),
     Yahoo Finance, and FactSet each classify stocks? What are their tier
     structures, how many levels, how many categories at each level?
  2. Where do these systems disagree with each other on specific companies?
     What are the most common misclassification patterns?
  3. What classification criteria do they use — revenue source, customer type,
     business model, market perception, earnings? How do they handle
     conglomerates and multi-segment companies?
  4. How often do they update classifications? What triggers a reclassification?
  5. What is the right granularity for a Rule One research taxonomy? How many
     sectors, industry groups, and industries should we have?
  6. How can we programmatically assign ~8,000 companies using ONLY freely
     available data (SEC EDGAR, Yahoo Finance, company 10-K filings, etc.)?
  7. What structural improvements over SIC would our taxonomy need — multi-segment
     support, modern industry categories, size-aware peer filtering?


## EXISTING CODEBASE CONTEXT

The app already has these components built:

  sicClassification.js — Hand-built map of ~250 SIC codes to
    { sector, industryGroup, industry, naics }. Organized into 11 sectors
    matching Morningstar-style naming. Has 2-digit major group fallback.
    Functions: getSICCodesForTier(), classifyBySIC().

  peers.js — Peer discovery engine. Takes SIC code → maps through
    sicClassification.js → finds all companies with matching SIC codes via
    SEC browse-edgar ATOM feed (primary) or EDGAR Frames API (fallback).
    Enriches with ticker symbols from EDGAR ticker index.

  peerMetrics.js — Fetches ~20 financial tags from EDGAR Frames API for
    latest calendar year. Yahoo Finance batch quotes fill gaps. Computes
    derived metrics: margins, ROE, ROIC, ROA, FCF, debt ratios. Data
    completeness scoring per peer.

  batchQuotes.js — Yahoo Finance batch quote fetcher with per-ticker caching.

  edgarFrames.js — EDGAR Frames API integration (tag definitions, fetching,
    cross-checking).

  useCompetitors.js — React hook orchestrating 3-phase progressive loading
    (peer discovery → metrics → Rule One scores).

  Competitors.jsx — Full UI: tier selector (Sector/Industry Group/Industry),
    industry benchmark card, sortable data table with 21 columns, percentile
    badges, sparse peer filtering, private competitor modal.

Data sources currently available (all free):
  - SEC EDGAR: company filings, SIC codes, XBRL financial data (Frames API),
    ticker index, company descriptions, CIK mapping
  - Yahoo Finance: live market data, their own sector/industry classifications
  - Finviz: analyst estimates, sector/industry labels
  - Company 10-K filings: revenue segment breakdowns, business descriptions,
    risk factors, competitor mentions

## TASK — PHASE 1: Research

Perform a thorough technical research deep dive. Complete in order:

  1. SURVEY ALL MAJOR TAXONOMY SYSTEMS
     Research each of these classification systems in depth:
       a. GICS (S&P/MSCI) — 4 tiers: 11 Sectors → 25 Industry Groups →
          74 Industries → 163 Sub-Industries. Uses 8-digit numeric codes.
          Revenue is primary, earnings secondary, market perception tertiary.
          Annual review. Companies get ONE classification only.
       b. Morningstar Global Equity Classification — 4 tiers: 3 Super Sectors
          (Cyclical/Defensive/Sensitive) → 11 Sectors → ~69 Industry Groups
          → ~148 Industries. Reviewed quarterly by analyst team.
          Uses 10-K/10-Q as primary source, 8-K for reorgs.
       c. ICB (FTSE Russell) — 4 tiers: 11 Industries → 20 Supersectors →
          45 Sectors → 173 Subsectors. Revenue-based, reviewed annually.
       d. Bloomberg BICS — Bloomberg Industry Classification System.
          Research structure, tier count, how it differs from GICS.
       e. Yahoo Finance — What taxonomy does Yahoo use? (Reportedly a
          modified version of Morningstar's system.) Document their sector
          and industry list.
       f. FactSet RBICS — Revenue-Based Industry Classification System.
          Multi-segment: assigns companies to MULTIPLE industries weighted
          by revenue share. Research this approach specifically.

     For each system, document:
       - Exact tier structure (how many levels, how many nodes at each level)
       - Classification criteria (what determines assignment)
       - How multi-segment / conglomerate companies are handled
       - Update frequency and what triggers reclassification
       - Whether classification data is freely available or paywalled

  2. BUILD A COMPARISON MATRIX
     Create a detailed comparison table across all 6 systems showing:
       - Tier depths and category counts
       - Primary classification signal (revenue vs. earnings vs. market perception)
       - Multi-segment handling (single assignment vs. multi-assignment)
       - Treatment of modern industries (SaaS, fintech, EVs, streaming, crypto, AI)
       - Where they disagree on specific well-known companies (Amazon, Alphabet,
         Tesla, Berkshire Hathaway, etc.)
       - Free data availability

  3. ANALYZE SIC vs. MODERN TAXONOMIES
     Document specifically:
       - What SIC gets wrong that GICS/Morningstar get right
       - The structural limitations (1937 design, no multi-segment, etc.)
       - Concrete examples of SIC misclassification in the current app
         (e.g., Amazon as "Catalog & Mail-Order Houses" SIC 5961)
       - What NAICS improves over SIC and where it still falls short

  4. IDENTIFY FREE DATA SOURCES FOR CLASSIFICATION
     Research and catalog every freely available data source that could
     inform automated company classification:
       a. SEC EDGAR submissions.json — SIC code, company name, CIK, filing history
       b. SEC EDGAR company_tickers.json — ticker/CIK/name mapping for all filers
       c. SEC EDGAR Frames API — financial data for classification signals
       d. SEC 10-K Item 1 (Business Description) — extractable via XBRL or
          full-text search
       e. SEC 10-K revenue segment disclosures — for multi-segment detection
       f. Yahoo Finance API — their sector/industry labels per ticker
       g. Finviz stock screener — sector/industry labels
       h. Wikipedia industry lists / company pages
       i. Open-source datasets (if any) that map tickers to GICS or similar
     For each source, note: URL/endpoint, data format, rate limits, coverage,
     reliability, and whether it requires an API key.

  5. DESIGN THE THES1S TAXONOMY STRUCTURE
     Based on all research above, propose a custom 3-tier taxonomy:
       Sector → Industry Group → Industry
     Design principles:
       - Optimized for Rule One investing (competitive analysis, moat assessment)
       - Groups companies by WHO THEY COMPETE WITH for customers/revenue
       - ~11-12 sectors (align with GICS/Morningstar where it makes sense)
       - ~50-70 industry groups
       - ~130-160 industries
       - Covers modern business models GICS/Morningstar cover but SIC doesn't
       - Explicit handling for: SaaS, platforms, fintech, digital advertising,
         EVs, streaming, cannabis, crypto/blockchain, AI/ML, cybersecurity,
         space, renewable energy, SPAC vehicles, blank check companies
       - Clear definitions for each node (what belongs here, what doesn't)
       - Decision rules for edge cases (conglomerates, holding companies, REITs,
         ADRs, SPACs, shell companies)

     IMPORTANT: The taxonomy design should include:
       - Numeric code system (similar to GICS 8-digit structure) for
         programmatic use
       - A mapping strategy from SIC → Thes1s taxonomy (since SIC is the
         starting data we already have for every company)
       - A mapping strategy from Yahoo Finance sectors/industries → Thes1s
         taxonomy (since Yahoo labels are freely available)
       - A confidence scoring system for classification quality

  6. DESIGN THE CLASSIFICATION PIPELINE
     Propose a multi-step programmatic pipeline for classifying all ~8,000
     actively traded US companies:

     Step 1 — Seed from existing labels
       Pull SIC codes from EDGAR → map through enhanced SIC map
       Pull Yahoo Finance sector/industry labels → map through crosswalk
       Where SIC and Yahoo agree → high confidence assignment
       Where they disagree → flag for deeper analysis

     Step 2 — NLP on business descriptions
       Extract Item 1 (Business Description) from latest 10-K for flagged
       companies. Use Claude API or keyword matching to determine primary
       business activity and assign taxonomy.

     Step 3 — Revenue segment analysis
       For multi-segment companies (detected via segment disclosure in 10-K),
       extract revenue breakdown and assign primary + secondary industries
       weighted by revenue share.

     Step 4 — Agent review queue
       Companies that couldn't be confidently classified go into a review
       queue for manual/agent-assisted classification.

     Step 5 — Ongoing maintenance
       How to handle new IPOs, delistings, M&A, business model pivots.
       Propose an update cadence and trigger conditions.

  7. DESIGN THE OUTPUT FILE FORMAT
     The taxonomy must be implementable as a replacement for sicClassification.js.
     Propose the data structure for:
       a. The taxonomy definition file (the tree itself — sectors, industry
          groups, industries, with codes and definitions)
       b. The company assignment file (maps CIK/ticker → taxonomy classification,
          with confidence score, assignment date, data sources used)
       c. The SIC crosswalk file (maps SIC codes → Thes1s taxonomy codes)
       d. The Yahoo crosswalk file (maps Yahoo labels → Thes1s taxonomy codes)
     All files should be static JSON or JS that can be imported directly.

  - Company tickers: https://www.sec.gov/files/company_tickers.json
  - Submissions (SIC, filing history): https://data.sec.gov/submissions/CIK##########.json
  - Frames API (financial data): https://data.sec.gov/api/xbrl/frames/{taxonomy}/{tag}/{unit}/{period}.json
  - Bulk data: https://www.sec.gov/Archives/edgar/daily-index/xbrl/companyfacts.zip
  - Bulk submissions: https://www.sec.gov/Archives/edgar/daily-index/bulkdata/submissions.zip
  - Rate limit: 10 requests/second with User-Agent header

Yahoo Finance:
  - Can be queried for sector/industry labels per ticker
  - Their taxonomy is reportedly based on Morningstar's system
  - Useful as a second classification signal to cross-reference against SIC

  - Helvetica body, Courier for code, title page, page numbers in footer

Bash / Code Execution:

Classification Pipeline:
  - The pipeline should be designed as a series of independent scripts
    that can be run sequentially or individually
  - Each step should output intermediate results that can be inspected
  - The final company assignments file should include provenance metadata

Multi-Agent Considerations:
  - This taxonomy will be used by multiple Claude Code agents working on

  - Design the taxonomy update process so it can be performed by an agent
