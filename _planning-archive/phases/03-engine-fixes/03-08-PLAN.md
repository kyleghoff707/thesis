**Part A: Methodology diff handlers in field-mapper.mjs**

Add these new special handlers to `getSpecialFieldHandlers()`:

1. **ppe_rou_methodology** — For `property_plant_equipment`, `property_plant_equipment_gross`, and `ppe_machinery` fields. Our engine includes ROU assets in PPE (matching FMP and MS's own "Leased Property" under Gross PPE). SimFin/mstarpy exclude ROU. The 49+24+28=101 DIFFs for these fields are consistent ROU inclusion differences. The handler should return `'METHODOLOGY_DIFF'` for these three thesisField values. Evidence from RESEARCH.md: "MS includes ROU in Net PPE per consolidated_vs_expanded intel report". AAPL PPE: engine $61B vs MS $50B — difference is exactly the ROU lease assets (~$11B).

```javascript
ppe_rou_methodology(thesisField) {
  const PPE_FIELDS = new Set([
    'property_plant_equipment',
    'property_plant_equipment_gross',
    'ppe_machinery',
  ]);
  if (PPE_FIELDS.has(thesisField)) return 'METHODOLOGY_DIFF';
  return null;
},
```

2. **goodwill_restated_methodology** — For `goodwill` field. MS uses restated values (retroactive accounting adjustments for acquisitions/impairments) while our engine extracts as-reported XBRL. Evidence: MET goodwill consistently ~$680M higher in MS across all years (restated post-acquisition adjustments). CRM 2025: MS $51.3B vs engine $57.9B (Slack acquisition restated differently). Return `'METHODOLOGY_DIFF'` for `goodwill`.

```javascript
goodwill_restated_methodology(thesisField) {
  if (thesisField === 'goodwill') return 'METHODOLOGY_DIFF';
  return null;
},
```

3. **lease_classification_methodology** — For `total_lease_liability_noncurrent` and `total_lease_liability_current`. MS separates operating vs finance leases differently than XBRL tags. BA: engine $1.9B vs MS $139M (engine includes both operating + finance NC lease, MS may only show one type). Return `'METHODOLOGY_DIFF'` for these two fields.

```javascript
lease_classification_methodology(thesisField) {
  const LEASE_FIELDS = new Set([
    'total_lease_liability_noncurrent',
    'total_lease_liability_current',
  ]);
  if (LEASE_FIELDS.has(thesisField)) return 'METHODOLOGY_DIFF';
  return null;
},
```

**Part B: Wire handlers into comparator.mjs**

In `compareCompany()`, after the existing bank_template_skip handler block (around line 120-134), add new handler checks. For each methodology handler, if the handler returns `'METHODOLOGY_DIFF'`, push a result with `status: 'METHODOLOGY_DIFF'` and `continue` (skip the normal comparison). The METHODOLOGY_DIFF status should be treated like MATCH in the accuracy calculation — it means the values differ but for known methodology reasons, not engine bugs.

Add this block after the bank_template_skip block:

```javascript
// Methodology diff handlers: PPE ROU, goodwill restated, lease classification
if (specialHandlers.ppe_rou_methodology) {
  const ppeResult = specialHandlers.ppe_rou_methodology(mapInfo.thesisField);
  if (ppeResult === 'METHODOLOGY_DIFF') {
    // Still compare — but if DIFF, reclassify as METHODOLOGY_DIFF
    // This lets genuine matches still count as MATCH
  }
}
```

IMPORTANT: The methodology handlers should NOT blindly skip. They should:
1. Run the normal comparison first
2. If the result is DIFF, reclassify the status to `METHODOLOGY_DIFF`
3. If the result is MATCH or CLOSE, keep the original status (genuine match is still valuable)

Implementation pattern:
```javascript
// After computing `comparison` result on line ~204-209:
// Check methodology handlers for DIFF results
if (comparison.status === 'DIFF') {
  const methHandlers = [
    specialHandlers.ppe_rou_methodology,
    specialHandlers.goodwill_restated_methodology,
    specialHandlers.lease_classification_methodology,
  ];
  for (const handler of methHandlers) {
    if (handler && handler(mapInfo.thesisField) === 'METHODOLOGY_DIFF') {
      comparison.status = 'METHODOLOGY_DIFF';
      break;
    }
  }
}
```

Also update the accuracy calculation in `lib/reporter.mjs` (if it counts statuses) — METHODOLOGY_DIFF should be excluded from the denominator, just like SKIP_BANK_TEMPLATE and SKIP_SPINOFF. Check `generateJsonReport` and `generateConsoleReport` to see how they count. If they only count MATCH/CLOSE/DIFF, then METHODOLOGY_DIFF being a different status will automatically exclude it.

**Part C: net_change_in_cash engine fix**

```javascript
// CURRENT (includes FX):
if (cf.net_change_in_cash == null) {

  const inv = cf.net_cash_flow_from_investing_activities;
  const fin = cf.net_cash_flow_from_financing_activities;

    cf.net_change_in_cash = op + inv + fin + fx;

```

Change to EXCLUDE FX:

```javascript
// Net change in cash = Op + Inv + Fin (excluding FX effect)
// MS "Change in Cash" = Op + Inv + Fin per DataID analysis.
// Verified: GOOGL 2021 MS=-5233M = Op(91652)+Inv(-35523)+Fin(-61362).
// Engine was adding FX(-287M) -> -5520M. MS excludes FX.
if (cf.net_change_in_cash == null) {
  const op = cf.net_cash_flow_from_operating_activities;
  const inv = cf.net_cash_flow_from_investing_activities;
  const fin = cf.net_cash_flow_from_financing_activities;
  if (op != null && inv != null && fin != null) {
    cf.net_change_in_cash = op + inv + fin;
  }
}
```

Also update `getDerivedFormula()` for `net_change_in_cash`:
