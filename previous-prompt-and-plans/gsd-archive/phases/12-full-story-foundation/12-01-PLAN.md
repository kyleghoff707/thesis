    **Create checklist-item.schema.json (per D-01, D-02, D-03):**

    This schema defines the structure of checklist items stored in the ReportSectionSchema `data` field (as a JSON string). Each checklist section (meaning_checklist, moat_checklist, management_checklist) uses this same format.

    ```json
    {
      "$schema": "http://json-schema.org/draft-07/schema#",
      "title": "ChecklistSectionData",
      "description": "Structured data for checklist sections (meaning, moat, management). Serialized as JSON string in ReportSectionSchema.data field.",
      "type": "object",
      "required": ["checklistType", "items", "summary"],
      "properties": {
        "checklistType": {
          "type": "string",
          "enum": ["meaning", "moat", "management"],
          "description": "Which checklist this is"
        },
        "items": {
          "type": "array",
          "description": "Individual checklist items with verdicts and evidence",
          "items": {
            "type": "object",
            "required": ["number", "item", "verdict", "evidence", "confidence"],
            "properties": {
              "number": {
                "type": "integer",
                "description": "Item number (1-15 for meaning/moat, 1-13 for management)"
              },
              "item": {
                "type": "string",
                "description": "The checklist question or criterion being evaluated"
              },
              "verdict": {
                "type": "string",
                "enum": ["PASS", "FAIL", "PARTIAL"],
                "description": "Binary conviction assessment per D-01. PASS = criterion clearly met, FAIL = criterion clearly not met, PARTIAL = evidence is mixed or insufficient"
              },
              "evidence": {
                "type": "string",
                "description": "1-2 sentence summary of the evidence supporting the verdict. Must cite specific data points or sources."
              },
              "confidence": {
                "type": "string",
                "enum": ["HIGH", "MEDIUM", "LOW"],
                "description": "Confidence in the verdict based on evidence quality. HIGH = multiple strong sources, MEDIUM = some evidence gaps, LOW = limited data"
              }
            }
          }
        },
        "summary": {
          "type": "object",
          "required": ["passCount", "failCount", "partialCount", "totalItems", "scoreDisplay"],
          "properties": {
            "passCount": {
              "type": "integer",
              "description": "Number of items with PASS verdict"
            },
            "failCount": {
              "type": "integer",
              "description": "Number of items with FAIL verdict"
            },
            "partialCount": {
              "type": "integer",
              "description": "Number of items with PARTIAL verdict"
            },
            "totalItems": {
              "type": "integer",
              "description": "Total number of items (15 for meaning/moat, 13 for management)"
            },
            "scoreDisplay": {
              "type": "string",
              "description": "Human-readable summary per D-03, e.g. '12/15 PASS, 2 PARTIAL, 1 FAIL'"
            }
          }
        }
      }
    }
    ```

    **Create debate-step.schema.json (per D-06, D-07, D-08, D-09):**

    This schema defines the lightweight format for each debate step. These are NOT full ReportSectionSchema objects -- they are intermediate outputs that get composed into the final S6 section.

    ```json
    {
      "$schema": "http://json-schema.org/draft-07/schema#",
      "title": "DebateStepOutput",
      "description": "Lightweight output format for each debate step. Per D-06: no charts, tables, or searchesPerformed on intermediate steps (except bear which has web search citations). Per D-08: All 4 outputs compose into the final S6 ReportSectionSchema.",
      "type": "object",
      "required": ["step", "role", "agent", "content"],
      "properties": {
        "step": {
          "type": "integer",
          "enum": [1, 2, 3, 4],
          "description": "Step number in the debate sequence"
        },
        "role": {
          "type": "string",
          "enum": ["bull", "bear", "bull_rebuttal", "judge"],
          "description": "The role this agent plays in the debate"
        },
        "agent": {
          "type": "string",
          "description": "Agent identifier (synthesis-writer, risk-analyst, or financial-analyst)"
        },
        "content": {
          "type": "object",
          "description": "Role-specific content (varies by step)",
          "oneOf": [
            {
              "title": "BullThesis",
              "description": "Step 1: Bull summarizes the investment thesis",
              "required": ["thesisPoints"],
              "properties": {
                "thesisPoints": {
                  "type": "array",
                  "items": {
                    "type": "object",
                    "required": ["point", "evidence", "sourceSection"],
                    "properties": {
                      "point": { "type": "string", "description": "A key argument for the investment" },
                      "evidence": { "type": "string", "description": "Supporting evidence from prior sections" },
                      "sourceSection": { "type": "string", "description": "Which prior section (S1-S5) this point derives from" }
                    }
                  }
                },
                "overallThesis": { "type": "string", "description": "1-2 paragraph summary of the complete bull case" }
              }
            },
            {
              "title": "BearInversion",
              "description": "Step 2: Bear attacks each bull point with evidence",
              "required": ["inversions"],
              "properties": {
                "inversions": {
                  "type": "array",
                  "items": {
                    "type": "object",
                    "required": ["targetPoint", "counterArgument", "evidence", "severity"],
                    "properties": {
                      "targetPoint": { "type": "string", "description": "The bull thesis point being attacked" },
                      "counterArgument": { "type": "string", "description": "The specific bear counter-argument" },
                      "evidence": { "type": "string", "description": "Cited evidence supporting the counter-argument (web search + DataPacket)" },
                      "severity": { "type": "string", "enum": ["thesis_killer", "significant", "minor"], "description": "How damaging this counter-argument is" },
                      "sources": { "type": "array", "items": { "type": "string" }, "description": "URLs and references for the evidence" }
                    }
                  }
                },
                "overallBearCase": { "type": "string", "description": "1-2 paragraph summary of the complete bear case" }
              }
            },
            {
              "title": "BullRebuttal",
              "description": "Step 3: Bull responds to each bear point",
              "required": ["rebuttals"],
              "properties": {
                "rebuttals": {
                  "type": "array",
                  "items": {
                    "type": "object",
                    "required": ["bearPoint", "rebuttal", "rebuttalStrength", "honest"],
                    "properties": {
                      "bearPoint": { "type": "string", "description": "The bear point being rebutted" },
                      "rebuttal": { "type": "string", "description": "The evidence-based counter to the bear argument" },
                      "rebuttalStrength": { "type": "string", "enum": ["strong", "moderate", "weak"], "description": "Honest assessment of rebuttal strength" },
                      "honest": { "type": "boolean", "description": "true if bear case is acknowledged as strong on this point (per D-09 -- honest acknowledgment)" }
                    }
                  }
                }
              }
            },
            {
              "title": "JudgeVerdict",
              "description": "Step 4: Judge scores each exchange and produces overall verdict",
              "required": ["exchanges", "overallVerdict"],
              "properties": {
                "exchanges": {
                  "type": "array",
                  "items": {
                    "type": "object",
                    "required": ["topic", "bullStrength", "bearStrength", "verdict", "reasoning"],
                    "properties": {
                      "topic": { "type": "string", "description": "The topic of the exchange" },
                      "bullStrength": { "type": "string", "enum": ["strong", "moderate", "weak"] },
                      "bearStrength": { "type": "string", "enum": ["strong", "moderate", "weak"] },
                      "verdict": { "type": "string", "enum": ["Strong Bull", "Strong Bear", "Unresolved"], "description": "Who won this exchange" },
                      "reasoning": { "type": "string", "description": "Why this verdict was reached" }
                    }
                  }
                },
                "overallVerdict": {
                  "type": "object",
                  "required": ["direction", "unresolvedCount", "summary"],
                  "properties": {
                    "direction": { "type": "string", "enum": ["Bull", "Bear", "Mixed"], "description": "Overall direction of the debate" },
                    "unresolvedCount": { "type": "integer", "description": "Number of Unresolved exchanges -- key risk metric" },
                    "summary": { "type": "string", "description": "2-3 paragraph summary of the overall debate outcome" },
                    "investmentImplication": { "type": "string", "description": "What the debate result means for the investment decision" }
                  }
                }
              }
            }
          ]
        }
      }
    }
    ```

    Both schemas are documentation-as-code -- they define the contract that agent prompts will reference when describing their output format. They live alongside the dispatch table because the orchestrator is responsible for composing these outputs.
