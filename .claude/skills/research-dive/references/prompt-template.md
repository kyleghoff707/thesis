## TOOL HINTS

Recommended tools and approaches for this research type:

Web & Documentation:
  - Use web_search for current state-of-the-art, recent developments,
    and authoritative sources (official docs, papers, RFCs)
  - Use web_fetch to retrieve full content from key URLs — don't rely
    on search snippets alone
  - Prioritize: official documentation > academic papers > engineering
    blogs > forums

File Operations:
  - Write incrementally — save notes as you go, don't accumulate
    everything in memory before writing
  - Use the notes file as a scratchpad during research, then synthesize
    into the final report

PDF Generation:
  - Use reportlab (Python) for the PDF — pip install reportlab
  - Follow the technical PDF formatting standard:
    Helvetica body, Courier for code, title page, page numbers in footer
  - Never use Unicode subscripts/superscripts — use <sub>/<super> tags

Bash / Code Execution:
  - If research involves code validation or testing, create a scratch
    script in the output dir and run it to verify findings
  - Document commands and outputs in the notes file

## Notes for Skill Use

- Always fill in ALL placeholders before saving the file — no `<PLACEHOLDER>` text
  should appear in the final .txt
- The plan mode directive at the bottom must always appear **verbatim and last**
- Adapt the Tool Hints section to the specific research domain described by the user
- If the user's research involves specific external services, APIs, or codebases,
  add those as tool hints (e.g., "Use GitHub search to find relevant repos")
