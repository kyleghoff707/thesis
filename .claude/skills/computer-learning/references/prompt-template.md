## TASK

Produce a thorough learning document and research report for the domain above.
Complete the following in order:

  1. Research the domain deeply — find authoritative sources, existing taxonomies,
     benchmarks, best practices, and known challenges for interpreting this data type
     in the specified domain.

  2. Synthesize the interpretation framework — derive step-by-step rules for how
     Claude should read, analyze, and classify items of this type, grounded in the
     research and the user's intake answers.

  3. Build the categorization schema — formalize the user-defined taxonomy into
     decision rules Claude can apply consistently.

  4. Document edge cases — identify known ambiguities and specify how to handle them.

  5. Write the Claude learning document (.md) — structured for direct injection into
     a Claude project knowledge base. See OUTPUT SPECIFICATION for full structure.

  6. Write the research notes file (.md) — raw sources, draft rules, and scratchpad.

  7. Generate the PDF report — human-readable technical version of the research and
     rationale. See OUTPUT SPECIFICATION for section structure.

### Learning Document Structure (<topic-slug>-learning.md)

Metadata block at top:
  ---
  title: <LEARNING TITLE>
  date: <YYYY-MM-DD>
  author: Computer Learning — Claude Code
  data-type: <TYPE>
  domain: <DOMAIN>
  project-folder: <PROJECT FOLDER>
  ---

Sections (adapt per data type — keep all that apply):
  1. Purpose & Scope
  2. Domain Overview
  3. Key Vocabulary & Labels
  4. Interpretation Framework
  5. Visual / Structural Patterns   ← for image/video/sensor
  6. Categorization Schema
  7. Edge Cases & Ambiguities
  8. Project-Specific Instructions
  9. Quick Reference (table)

Writing standard: imperative, direct, no filler. Written as instructions to Claude.
"When you see X, do Y." Use tables for taxonomies. Use code blocks for output formats.

### PDF Report Structure (<topic-slug>-learning-report.pdf)

  1. Executive Summary
  2. Learning Objective & Data Type

     3.2 Key Concepts & Terminology
     3.3 Existing Standards / Taxonomies / Benchmarks
  4. Interpretation Framework (rationale)
  5. Categorization Schema (rationale)
  6. Edge Cases & Known Challenges
  7. Project Integration Notes
  8. References & Sources

PDF formatting: reportlab, Helvetica body, Courier for code, title page, page numbers
in footer. Never use Unicode subscripts — use <sub>/<super> tags in Paragraph text.

## TOOL HINTS

Research & Sources:
  - Use web_search to find domain-specific interpretation standards, benchmarks,
    datasets, and expert resources
  - Use web_fetch to retrieve full content from key URLs — don't rely on snippets
  - For image domains: look for computer vision papers, annotation guides, labeling
    schemas (e.g., COCO, ImageNet, domain-specific datasets)
  - For literature domains: look for field-specific review papers and metadata schemas
  - For video domains: look for action recognition benchmarks and temporal annotation guides
  - Prioritize: official docs / papers > domain-specific guides > engineering blogs

File Operations:
  - Write the notes file incrementally as you research
  - Draft the learning .md sections as you synthesize each topic area
  - Finalize the .md before generating the PDF (PDF derives from the same research)

PDF Generation:
  - Use reportlab (Python): pip install reportlab --break-system-packages
  - Follow the technical PDF formatting standard from the skill's pdf-formatting reference
  - Title page, page numbers in footer, Helvetica body, Courier for code blocks

## Notes for Skill Use

- Always fill in ALL placeholders before saving the file — no `<PLACEHOLDER>` text
  should appear in the final .txt
- The plan mode directive at the bottom must always appear **verbatim and last**
- The `<PROJECT FOLDER>` path must be explicitly confirmed during intake — do not
  assume or infer it
- The domain-specific tool hints section must be customized to the actual domain
  the user described — do not leave generic placeholder text
- If the user described multiple data types, add an intake summary entry for each type
  and adjust the task list and output structure accordingly
