## Problem Statement

Thes1s's XBRL engine extracts financial data from SEC EDGAR and needs to match Morningstar's standardized output — the same data source R1 Toolbox uses. The previous engine restructure introduced silent regressions (NCL 98% too low, D&A 90% too low) because the validation system measured *tag existence*, not *value accuracy*. Without a robust verification system, every engine change risks introducing regressions that corrupt Rule One scores and valuation calculations.

The verification system must answer one question with certainty: **"Does Thes1s produce the same numbers as Morningstar for this company?"**

## Demand Evidence

- The founder is their own first customer — 8+ years of Buffett-style investing, enrolled in Phil Town's advanced course, transitioning from engineering to professional money management
- R1 Toolbox (the existing paid product) is a pure presentation layer on top of Morningstar — zero transformations. If Thes1s matches Morningstar, it matches R1 automatically
- The 40+ hour per-company research process is a known pain point across the Rule One student community
- Trust is holistic: "If someone compares Thes1s to R1 Toolbox and sees missing fields, they won't trust ANY of the numbers"

## Status Quo

Rule One investors currently pay for R1 Toolbox (Morningstar data) and then spend 20-40 hours per company doing manual research on top of it. The toolbox provides the financial data; the human does all the analysis work. There is no AI-assisted Rule One research tool.

## Target User & Narrowest Wedge

**Target user:** The founder themselves — a serious Rule One investor who wants to research more companies faster and eventually manage money professionally.

**Narrowest wedge:** Accurate financial data extraction from free SEC sources that matches Morningstar's standardized output. This is the prerequisite for everything else (AI research assistant, valuation calculators, growth rate analysis). Without trusted data, the research workflow has no foundation.

## Constraints

1. No Morningstar subscription — data must come from free SEC EDGAR XBRL filings
2. Morningstar's website blocks headless browsers (CAPTCHA) — no automated scraping of Morningstar directly
3. stockanalysis.com (Fiscal.ai source) is scrapable and matches ~55 core Morningstar fields, but Morningstar has ~230 fields with deep hierarchies
4. The user will manually download Morningstar CSVs for the 50-company truth set (and on-demand additions), but doesn't want to spend hours doing it regularly
5. Must integrate with existing vitest infrastructure (173 tests)

## Premises

1. **Full Morningstar field parity is the goal.** Trust is holistic — if any field is missing or wrong, users won't trust the scoring fields either.
2. **The data extraction layer is the competitive moat.** The product is the AI research assistant (One Pager → Pitch Deck → Full Story), but owning accurate financial data from free SEC sources makes it defensible and free from Morningstar dependency.
3. **Three-layer verification:**
   - Layer 1: 50-company deep truth set (all Morningstar fields, downloaded upfront)
   - Layer 2: Automated stockanalysis.com scraping (~55 fields, any ticker, on-demand regression checks)
   - Layer 3: On-demand expansion — when edge cases arise that the 50 don't cover, manually download Morningstar CSVs for specific companies as needed

## Approaches Considered

### Approach A: "Golden File Testing" — Minimal Viable
Parse 30 Morningstar CSVs into normalized JSON "golden files." Build a comparison script that extracts Thes1s data and diffs against golden files. Manual field mapping table. Separate stockanalysis.com scraping script for Layer 2.

- **Effort:** M | **Risk:** Low
- **Pros:** Simplest to build, fastest to first results, field mapping becomes documentation
- **Cons:** Manual to run, no visual feedback, field mapping maintenance is tedious

### Approach B: "Automated Regression Suite" — Ideal Architecture
Morningstar data encoded as vitest test fixtures. Every field, every company, every year = a test assertion. `npm test` catches regressions automatically on every code change. stockanalysis.com scraping as additional dynamically-fetched test cases.

- **Effort:** L | **Risk:** Low
- **Pros:** Catches regressions automatically, integrates with existing vitest (173 tests), failed tests show exact field/company/year/delta, CI-ready
- **Cons:** Large test file, harder to browse visually, network dependency for stockanalysis.com tests

### Approach C: "Living Comparison Dashboard" — Creative/Lateral
Developer mode in Thes1s's Audit tab showing Morningstar vs Thes1s side-by-side. Load golden files for 30 truth companies, scrape stockanalysis.com for any other ticker on demand. Color-coded visual diff.

- **Effort:** L | **Risk:** Med
- **Pros:** Visual feedback during development, could become product feature
- **Cons:** Doesn't catch regressions automatically, more UI code to maintain

## Recommended Approach

**Approach B: Automated Regression Suite.** Regressions are the #1 enemy — the previous XBRL restructure introduced silent regressions that undid correct values. An automated test suite that runs on `npm test` is the only approach that catches regressions *before* they ship. The existing 173 vitest tests establish the pattern.

### Implementation Architecture

#### Layer 1: Deep Truth Test Suite (50 companies × ~230 fields × 5 years)

**Step 1 — Morningstar CSV Parser**
Build a script (`scripts/morningstar-to-fixtures.cjs`) that:
- Reads all Morningstar CSVs from `knowledge/Morningstar Financial Statements/`
- Normalizes field names (strips indentation hierarchy, standardizes naming)
- Converts values from Morningstar format (e.g., `365817000000.`) to millions
- Outputs a single JSON fixture file per company: `src/engines/__tests__/fixtures/morningstar/{TICKER}.json`

Fixture format:
```json
{
  "ticker": "AAPL",
  "source": "morningstar",
  "statements": {
    "income": {
      "2024": {
        "revenue": 391035,
        "cost_of_revenue": 210352,
        "gross_profit": 180683,
        ...
      }
    },
    "balance_sheet": { ... },
    "cash_flow": { ... }
  }
}
```

**Step 2 — Field Mapping Table**
Create `src/engines/__tests__/fixtures/morningstar/field-mapping.json` that maps every Morningstar CSV field name to the corresponding Thes1s field name. This is the critical artifact — it documents exactly how Morningstar's taxonomy maps to Thes1s's taxonomy.

```json
{
  "income": {
    "Total Revenue": "revenue",
    "Cost of Revenue": "cost_of_revenue",
    "Selling, General and Administrative Expenses": "sga",
    "Research and Development Expenses": "research_and_development",
    ...
  },
  "balance_sheet": { ... },
  "cash_flow": { ... }
}
```

**Step 3 — Comparison Test Suite**
Create `src/engines/__tests__/morningstarAccuracy.test.js`:
- For each of the 50 companies, extract financial data via the XBRL engine
- Compare every mapped field against the Morningstar fixture
- Tolerance tiers:
  - **Exact** (within $1M or 0.1%): Revenue, Net Income, Operating CF, CapEx, Total Assets, Equity, EPS
  - **Close** (within 1%): SGA, R&D, Operating Income, D&A, Dividends Paid, Share Repurchases
  - **Approximate** (within 5%): Total Debt, Net Debt, EBITDA, Working Capital, Invested Capital
  - **Loose** (within 20%): Financial-sector Total Debt (BRK.B, JPM, O, MET)
  - **Informational** (no fail): Fields not yet mapped or known-divergent
- Each failed assertion shows: company, field, year, expected value, actual value, delta %

**Step 4 — Coverage Report**
After tests run, output a summary:
```
MORNINGSTAR ACCURACY REPORT — 50 companies
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
AAPL:  142/148 fields match (96.0%)  — 4 close, 2 missing
LULU:  138/148 fields match (93.2%)  — 6 close, 3 missing, 1 MATERIAL DIFF
...
OVERALL: 6,900/7,400 (93.2%) exact | 330 close | 70 missing | 100 MATERIAL DIFF
```

#### Layer 2: Automated Regression Tests (stockanalysis.com scraping)

**stockanalysis.com Technical Details (validated 2026-03-19):**
- No CAPTCHA, no login required, no API key needed
- Data source: Fiscal.ai (same underlying Morningstar/S&P standardized data)
- URL pattern: `stockanalysis.com/stocks/{ticker}/financials/` (IS), `/balance-sheet/` (BS), `/cash-flow-statement/` (CF)
- Data is in standard HTML `<table>` elements — extract with `document.querySelectorAll('tr')`, each row's `th`/`td` cells give field name + year values
- Has "Standardized" and "As Reported" toggle, Annual/Quarterly/TTM buttons
- Handles industry-specific fields: banks (NII, Provision for Credit Losses), REITs (Property Revenue, Gains on Disposal)
- **Field coverage: ~105 rows per company (~35 per statement), of which ~55 overlap with Morningstar's ~230 fields**
- What's missing vs Morningstar: debt maturity schedules, gross PP&E / accumulated depreciation, lease obligation breakdowns, sub-breakdowns (Trade vs Other Receivables), supplemental items (Tax Paid, Interest Paid)
- Values for overlapping fields are **byte-for-byte identical** to Morningstar (verified AAPL FY2024 across all core IS/BS/CF fields)
- Morningstar.com itself is **blocked** (Cloudflare CAPTCHA on headless browsers) — stockanalysis.com is the automated alternative
- macrotrends.net also works (no CAPTCHA) but uses Zacks data (different standardization) and jqx grid widget (harder to parse)

**Step 5 — Scraper Module**
Create `scripts/scrape-stockanalysis.cjs`:
- Takes a ticker, scrapes IS/BS/CF from stockanalysis.com
- Returns structured JSON matching the fixture format
- Handles: Annual/Quarterly/TTM views, "Standardized" mode
- Caches results to avoid hammering the site (24-hour cache in `/tmp`)
- Rate limiting: 2-second delay between page loads

**Step 6 — Dynamic Test Suite**
Create `src/engines/__tests__/stockanalysisRegression.test.js`:
- Runs for a configurable list of tickers (default: the 50 truth companies)
- Can be expanded to any ticker on demand via env var: `TICKERS=AAPL,GOOG npm test`
- Only tests the ~55 fields that stockanalysis.com provides
- Uses same tolerance tiers as Layer 1
- Skipped by default in CI (network dependency) — run manually with `npm run test:regression`

### Accounting Standard Changes — Morningstar Restated vs EDGAR As-Filed Divergence

When comparing Morningstar Restated data against XBRL as-filed data, these accounting changes create **expected divergences** that are NOT bugs. The test suite must categorize these as informational flags, not failures.

#### Critical: Corporate Spin-offs (Discontinued Operations)

| Ticker | Event | Years Affected | Revenue Difference |
|--------|-------|---------------|-------------------|
| **T** | WarnerMedia spin-off → WBD (Apr 2022) | 2020-2021 restated | ~$35-48B/yr — Morningstar restates prior years to continuing ops only; EDGAR as-filed 2020-2021 10-Ks show full consolidated including WarnerMedia |
| **JNJ** | Kenvue spin-off (Aug 2023) | 2021-2022 restated | ~$15B/yr — Morningstar excludes Consumer Health from prior years; original 2021-2022 10-Ks include it |

**Impact on test suite**: Pre-spin years should use **informational** tolerance tier, not strict. EDGAR Frames API may return original or restated values depending on which filing it sources from.

#### High: ASC 842 — Lease Accounting (effective 2019)

Operating lease ROU assets and liabilities moved onto the balance sheet. XBRL tags `OperatingLeaseRightOfUseAsset` and `OperatingLeaseLiability*` did not exist before 2019. Morningstar Restated may retroactively add these to pre-2019 periods.

**Most affected from the 50 (lease liabilities >20% of total liabilities):**
CMG, SBUX, TXRH, BOOT, ULTA, LULU, WSM, SFM

**Significantly affected (>10%):**
AMZN, DAL, COST, NKE, TSCO, POOL, ODFL, AMT, EQIX, O, GOOGL, META, CRM

**Impact on test suite**: Balance sheet Total Assets and Total Liabilities may diverge for pre-2019 years. Income statement impact is minimal (straight-line lease expense unchanged).

#### Moderate: ASC 326 — CECL Credit Losses (effective Jan 2020)

Banks changed from "incurred loss" to "lifetime expected credit loss" model. Modified retrospective transition — prior years NOT restated in EDGAR filings.

| Ticker | Day-1 Impact |
|--------|-------------|
| **JPM** | +$4.3B allowance increase (credit card allowance nearly doubled) |
| **WFC** | -$1.3B allowance decrease (shorter contractual maturities) |
| **MET** | ~$400M mortgage allowance increase |

**Impact on test suite**: One-time cumulative adjustment to retained earnings in Q1 2020. Morningstar may smooth this. Non-financial companies have negligible impact.

#### Moderate: ASC 944 — LDTI Insurance Accounting (effective Jan 2023)

Overhauled long-duration insurance contract accounting. **Retrospective to Jan 1, 2021** — companies restated 2021-2022 in their 2023 10-K.

| Ticker | Impact |
|--------|--------|
| **MET** | DAC, VOBA, embedded derivative reclassifications. Pre-tax earnings restated for 2021-2022. |
| **BRK-B** | Insurance operations affected. Restated 2021-2022 underwriting results. |

**Impact on test suite**: EDGAR CompanyConcept API may return original or restated values for 2021-2022 depending on which filing is sourced. Frames API should return latest (restated) values.

#### Low: ASU 2020-06 — Convertible Debt Simplification (effective Jan 2022)

Eliminated cash conversion and BCF models for convertible debt. Lower interest expense, higher reported debt. Minimal impact for this group of large-cap companies (most use traditional senior notes).

#### Informational Only (no number impact): ASU 2023-07 (Segment Reporting), ASU 2023-09 (Tax Disclosures)

Disclosure-only changes — do not affect reported numbers. No Morningstar vs EDGAR divergence.
