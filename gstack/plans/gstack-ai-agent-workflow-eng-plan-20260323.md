## Section 1: Architecture Review — 3 Issues Found

### Issue 1: Data Bridge Is Harder Than Estimated

**Finding**: The plan estimated ~200 LOC for the Node.js adapter. The outside voice identified 5 Vite proxy routes, 3 middleware plugins, 13 files using DOMParser, and 17 `import.meta.env` checks. Real estimate: ~500-800 LOC.

**Decision**: Build Node.js adapter layer (Option B). Swaps browser APIs for Node equivalents. Engine logic unchanged. Foundation for CC skills AND future commercial backend. Phase 5A estimate adjusted to 5-7 days.

**Rationale**: The adapter is permanent infrastructure. Prototyping shortcuts (gstack /browse scraping, manual JSON export) create tech debt. The adapter also becomes the core of the future Cloudflare Workers backend.

### Issue 2: Toolbox Tools Execution Path

**Finding**: The plan lists 12 callable Toolbox tools (computeMOS, getMetric, etc.) but doesn't specify HOW subagents call them. In CC mode, Agent tool subagents get text in/text out — they can't call JavaScript functions directly.

**Decision**: The orchestrator handles tool execution. Subagent requests a tool call in its output → orchestrator parses it → orchestrator runs the function → orchestrator injects the result into the agent's next prompt (or spawns a continuation). This is the standard CC Agent tool pattern.

### Issue 3: Failure Handling Strategy

**Finding**: No failure handling was specified. Three failure modes: agent crashes, agent produces garbage, agent can't find data.

**Decision**: Retry once with error feedback, then escalate to user. Matches the PM/analyst model — if the analyst can't figure it out after two tries, they come to you.

## Prototype Validation Results (2026-03-23)

Ran the $0.15 experiment before building. Key findings:

- **One Pagers**: Single agent with DataPacket + template = good quality. Confirmed.
- **Pitch Decks**: Single agent quality degrades fast. LULU attempt regurgitated the example instead of doing fresh analysis. TSCO (no example) was clearly worse.
- **Conclusion**: Multi-agent architecture confirmed necessary for pitch deck quality.

**New requirements discovered:**
1. **No example contamination** — Agents must NOT pattern-match from LULU examples
2. **Visual evidence capture** — Agents must screenshot notable charts/diagrams during web research
3. **Academic-style citations** — Numbered `[1]`, `[2]` inline references with source list
4. **Prototype DataPacket gaps** — Quick scripts missed guru holdings (Phil Town on LULU, Rolfe/Dalio on TSCO). Production DataPacket via real engines will be complete.
