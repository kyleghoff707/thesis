## Goal

Match Morningstar's standardized financial statement output from the same SEC EDGAR XBRL source data. Annual data only, 5 years back, restated values. 50-company truth set. If we match Morningstar, we match R1 Toolbox automatically (R1 is a pure presentation layer on Morningstar).

**NOT in scope:** R1 conversion logic, quarterly data, TTM, Layer 2/3 rebuild, stockanalysis.com scraper, full MS field parity (~145 extra fields), financial-statement-taxonomy-mapping skill, direct iXBRL parsing.

## Phase A Detail

### A1: Morningstar CSV Parser

**File:** `scripts/morningstar-to-fixtures.cjs`

**Input:** `knowledge/Morningstar Financial Statements/{TICKER}/` — 3 CSVs per company (IS, BS, CF)

**Output:** `src/engines/__tests__/fixtures/morningstar/{TICKER}.json`

**Fixture format:**
```json
{
  "ticker": "AAPL",
  "source": "morningstar",
  "currency": "USD",
  "fiscalYearEnd": "Sep 30",
  "statements": {
    "income": {
      "2024": {
        "Total Revenue": 391035000000,
        "Cost of Revenue": -210352000000,
        "Gross Profit": 180683000000,
        ...
      }
    },
    "balance_sheet": { ... },
    "cash_flow": { ... }
  }
}
```

**CSV format quirks to handle:**
- Header: `{TICKER}_{statement-type}_Annual_Restated,{Year1},...,{YearN}[,TTM]`
- Field names: indented with spaces (hierarchy), quoted if commas present
- Values: whole dollars with trailing decimal (365817000000.), negatives with leading minus
- Empty cells: `,,` = null (not 0)
- Last row: `Fiscal year ends in {Month} {Day} | {Currency}` — parse for FY end + currency
- IS/CF: 5 years + TTM column. BS: 5 years, no TTM
- Duplicate rows at bottom (EPS rows appear twice) — deduplicate

**Fiscal year offset handling (9 companies):**
LULU (Jan 31), ULTA (Jan 31), WSM (early Feb), BOOT (Jan/Feb), NKE (May 31), COST (Aug/Sep), CRM (Jan 31), INTU (Jul 31), NVDA (Jan 31).

Morningstar labels by calendar year the FY ends. EDGAR labels by the company's stated FY designation. Parser detects offset from FY end month and shifts year labels to match EDGAR convention.

Example: LULU FY ending Jan 31, 2023 → MS labels "2023" → Parser shifts to "2022" (EDGAR's FY2022).

**Built-in validation:**
- Spot-check known values (AAPL 2024 revenue = $391,035M)
- Verify field counts per statement type
- Flag anomalies (unexpected nulls, sign inconsistencies)
- Output validation report alongside fixtures

### Implementation Decisions Made

1. **FY offset detection:** Auto-detect via revenue matching. Bias toward offset=0 — only use offset=-1 if ≥3 revenue values match within 2%. Prevents false positives from coincidental near-matches.
2. **EUR companies:** Skip from comparison (RACE). Cross-currency comparison is out of scope.
3. **Fetch interceptor:** Rewrites Vite dev proxy URLs (`/api/edgar/...`) to direct SEC URLs (`https://data.sec.gov/...`) with User-Agent header. Disk-cached for fast reruns.
4. **Rate limiting:** 100ms between SEC requests (10 req/sec). Respects SEC fair use policy.
5. **Tolerance enforcement:** Field-level tolerance from mapping, with company-level overrides (financial sector gets relaxed tolerance on revenue/debt).
6. **Spin-off handling:** JNJ pre-2023 and T pre-2022 years are SKIP_SPINOFF (informational, not failures).
7. **Baseline mode:** Tests currently pass if any comparisons succeed. Tighten to assert on material diffs after Phase B.

### What Worked (B5)

**PP&E + ROU derivation:** Morningstar includes `OperatingLeaseRightOfUseAsset` in "Net PPE". Added derivation: `property_plant_equipment += operating_lease_rou_asset`. Same for gross PP&E. **Result: 160 → 49 failures (-111)**. Remaining 49 are years where MS inconsistently excludes ROU (e.g., AAPL 2022+ vs 2021).

**Intangible asset taxonomy split:** Separated `FiniteLivedIntangibleAssetsNet` and `IndefiniteLivedIntangibleAssetsExcludingGoodwill` into their own fields (`finite_lived_intangibles`, `indefinite_lived_intangibles`). Added derivation to sum them when the combined `IntangibleAssetsNetExcludingGoodwill` tag is null. **Result: 150 → 149 failures (-1)**. Minimal improvement because most failures are from companies whose intangible totals don't match any of the three XBRL tag families (e.g., AMAT 2021: MS=2041M, engine=104M — significant unreachable gap).

**Lease liability mapping fix:** MS "Capital Lease Obligations" = ALL lease liabilities (operating + finance combined), not just finance leases. Created derived `total_lease_liability_current/noncurrent` fields summing both types. Updated field mapping to point to derived fields. **Result: eliminated 127 finance_lease failures from top 15 list.**

### What Didn't Work

**D&A amortization addition (reverted):** Attempted to add `amortization_of_intangibles` when `depreciation_amortization` seemed incomplete. Blew up from 62 → 204 failures because most companies' `DepreciationDepletionAndAmortization` already includes amortization; the heuristic couldn't distinguish. **Root cause: CRM-type companies (8 total) report D&A and intangible amortization as separate CF line items — a non-standard practice that requires per-company tag inspection, not a global derivation.**

**B7 residual "Other" computations (reverted):** Computed "Other" fields as `Total - Σ(named items)` per the plan. Blew up catastrophically — AAPL other_investing went from -385M to -194B (500x error). **Root cause: the residual formula amplifies any error in named items. Since sale_of_investments, purchase_of_investments, and other named CF items still have significant tag gaps, the residuals absorbed these errors and produced wildly wrong values. B7 MUST wait until B5 named item coverage is much higher.**

**Files:** `src/engines/edgarFinancials.js` (`computeDerivedFields` function)

**Approach:** "Other" fields in Morningstar are NOT direct XBRL tags — they're computed as the residual: **Total line item minus the sum of all named line items.** This is how an accountant designs a normalized financial statement: everything has a home, and "Other" is the gap.

Currently the engine probably maps "Other" to a single XBRL tag (like `OtherOperatingIncomeExpenseNet`). Morningstar computes it as a remainder. The fix is to match Morningstar's approach:

```
other_financing = net_cash_flow_from_financing_activities
                  - proceeds_from_lt_debt - repayments_of_lt_debt
                  - share_repurchases - proceeds_from_stock_issuance
                  - dividends_paid - (net ST debt change)

other_investing = net_cash_flow_from_investing_activities
                  - capital_expenditures - purchase_of_investments
                  - sale_of_investments - purchase_of_business
                  - sale_of_business

other_income_expense = income_before_tax - operating_income_loss
                       - net_interest_income

change_in_other_working_capital = (CFO working capital change total)
                                  - change_in_receivables
                                  - change_in_payables
                                  - change_in_inventory

other_noncash_items = (CFO noncash adjustment total)
                      - depreciation_amortization
                      - stock_based_compensation
                      - deferred_income_tax
```

**Important:** These residual computations only work if the "Total" line items are correct AND the named items are correct. That's why this step comes after B5 and B6.

**Expected improvement:** Many of the 527 residual failures will auto-resolve after B5/B6 improve the named items that feed into the residual calculation. The remaining failures indicate either: (a) a named item we missed, or (b) a genuine classification difference between MS and XBRL.

**Verify:** Run accuracy suite. Track improvement delta from B5/B6 alone vs after B7 residual computation.

### Key Learnings

- **MS definitions describe internal normalization, not raw XBRL mapping.** Many proposed fixes that matched MS formulas exactly regressed in practice because the engine maps XBRL tags directly, not through MS's normalization pipeline.
- **Tags that work for one company break others.** XBRL has enormous cross-company variation. Any tag change must be validated across all 50 companies, not spot-checked.
- **Honest tolerance reclassification is legitimate.** The 4 residual fields and 4 structural fields are genuinely different computations — marking them as such isn't cheating, it's accuracy.
- **Blocked residual "Other" fields remain unfixable** (attempted 4 times total: B7, B8, post-research, this pass). Error amplification is fundamental.
